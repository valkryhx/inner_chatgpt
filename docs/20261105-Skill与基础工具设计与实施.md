# Skill 模块 + 基础工具（P1）设计与实施

> 阶段：P1（去 LangChain 之后的第一能力增强）。
> 目标：在 **不引入 langchain / langgraph、不 import GenericAgent** 的前提下，
> 让 Web Agent 具备「读文件 / 写文件 / 局部改文件 / 跑代码 / 加载 Skill」这组最小可用的
> 自主执行工具，并把 Skill（SKILL.md）做成可被模型按需加载（渐进披露）的能力。
>
> 参考实现：`D:\git_codes\GenericAgent\genericagent\core\skills.py`、
> `genericagent/core/handler.py`；`D:\git_codes\Aivory\server\internal\tools\builtins.go`
> 与 `server/internal/llm/orchestrator_context.go`。**只借鉴设计，不复制 CLI 总装层。**

---

## 1. 为什么要先做这一层

当前内核只有「模型 + MCP 工具」。MCP 适合外部系统集成，但缺少一个 Agent 自主闭环最基础的能力：

- 读到真实文件内容，而不是靠记忆猜；
- 把结果写回文件；
- 用代码执行来验证「算得对不对 / 跑不跑得通」；
- 把一个可复用的操作手册（Skill）按需加载进上下文。

没有这层，后续的 subagent / team / task / 计划模式 / goal / hooks 都无处落脚 ——
它们最终都要靠「读、写、跑」去落地。所以本阶段是后续高级特性的地基。

## 2. 设计原则

1. **轻量、可替换、可扩展**：所有工具都是 `Tool` 对象，与 MCP 工具同构，注册进同一个
   `ToolRegistry`，模型侧无差别调用。
2. **用户隔离**：文件操作全部限制在当前用户的 workspace 目录内；Skill 也按用户隔离。
3. **失败不抛异常**：工具内部错误统一返回可读文本，模型可自纠（沿用 `ToolRegistry.dispatch`）。
4. **渐进披露**：系统提示只放 Skill 的「名称 + 一句话描述」清单（L1），正文通过
   `load_skill` 工具按需加载（L2），避免把几十个 SKILL.md 全塞进每轮 prompt。
5. **目录即事实**：Skill 以文件系统为准（`.../<name>/SKILL.md`），不额外建表。
   好处：可直接用编辑器/版本管理维护、与 Claude Code / Codex 的 Skill 格式天然兼容。

## 3. Skill 存储与格式

### 3.1 两类来源

| 来源 | 路径 | 归属 | 可见性 |
|---|---|---|---|
| 内置 Skill | `backend/skills_builtin/<skill-name>/SKILL.md` | 仓库只读 | 所有用户 |
| 用户私有 Skill | `backend/data/skills/<user_id>/<skill-name>/SKILL.md` | 单用户可写 | 仅本人 |

- 两者在列表里合并展示，用户私有同名 Skill **覆盖**内置同名 Skill（便于用户自定义）。
- 用户私有目录首次写入时才创建；删除 Skill = 删除该用户目录下的 `<name>` 子目录（含其附带文件）；
  删除前会把目标路径 `resolve()` 并校验严格位于该用户的 skill 根目录下，杜绝越界删除。

### 3.2 SKILL.md 格式

与 Claude Code / Codex / GA 一致：YAML frontmatter + Markdown 正文。

```markdown
---
name: pdf-report
description: 把数据整理成 PDF 报告，含图表与结论
---

# PDF 报告

步骤：1) 用 file_read 读取数据 … 2) 用 code_run 生成图表 … 3) 汇总输出。
可引用本目录下的文件：${SKILL_DIR}/templates/report.md
```

- `name`：缺省取目录名。要求 `[a-z0-9-]`，长度 ≤64（保存时校验）。
- `description`：缺省取正文第一个标题/首行，上限 250 字符展示。
- 正文可用占位符：`${SKILL_DIR}`（本 Skill 目录绝对路径）、`$ARGUMENTS`（调用参数）。

### 3.3 路径安全

所有按名字解析的 Skill 目录都要 `resolve()` 后校验仍位于允许根目录内，
拒绝 `..`、绝对路径、符号链接逃逸。用户名目录同理（`SKILLS_DIR / user_id`）。

### 3.4 为什么用「每用户目录」而不是数据库表（与 Aivory 的差异）

Aivory 把用户私有 Skill 存进 SQLite 的 `user_skills` 表（`user_id` 隔离），
管理员 catalog 存 `skills` 表，用户可「从 catalog 复制」。这套做法适合它的场景，
但本项目选择**文件系统 + 每用户目录**，理由：

1. **SKILL.md 天然是文件**：Claude Code / Codex / GenericAgent 都用 `SKILL.md`，
   直接落盘即可与这些生态互通（复制目录就能导入），不需要序列化/反序列化。
2. **Skill 允许带附带文件**：真实 Skill 常带模板、脚本、参考资料（`${SKILL_DIR}/templates/...`）。
   目录可以原样放这些文件；存 DB 只能存正文，反而要再单独维护附件目录。
3. **可直接用编辑器 / 版本管理维护**：排障时直接看/改文件，无需写 SQL。
4. **实现简单、无迁移负担**：不需要新增表与 DAO；`user_id` 通过目录隔离即可。

代价是「列表/审计」需要扫目录（本阶段 Skill 数量很小，可忽略）。若将来 Skill 数量大、
需要分页/搜索/审计，可再加一张 `user_skills` 元数据表做**索引缓存**，但**目录仍是权威来源**。
这就是「后台按用户各自的 skills 目录保存」的落地方式：`backend/data/skills/<user_id>/<name>/SKILL.md`。

## 4. 基础工具清单（本阶段）

| 工具 | 作用 | 关键约束 |
|---|---|---|
| `file_read` | 读文本文件（带行号 / 分页 / 关键字定位） | 仅允许读 workspace 或本人可见 Skill 目录内 |
| `file_write` | 写文件（overwrite / append / prepend） | 仅允许写本人 workspace（自动建父目录） |
| `file_patch` | 唯一匹配替换（old→new） | 仅学 workspace；匹配 0 或 >1 处都报错并提示 |
| `code_run` | 跑 Python 脚本 / PowerShell 命令 | cwd 限定 workspace；超时；输出截断；非交互 |
| `load_skill` | 按名字加载 SKILL.md 全文 | 仅加载当前用户可见 Skill；替换占位符 |
| `list_files` | 列 workspace（或 Skill 目录）文件树 | 只读；有深度与数量上限 |

> 命名沿用 GenericAgent（`file_read / file_write / file_patch / code_run`），
> 便于对照参考实现；对模型而言名字只是标识，不影响能力。

### 4.1 权限边界（MVP）

- **读**：workspace + 当前用户可见的全部 Skill 目录（内置 + 私有）。
- **写/改**：仅 workspace。不能改仓库源码、不能改 Skill 正文（Skill 通过 API 管理）。
- **代码执行**：MVP 是「受控子进程」，不是强沙箱：
  - 工作目录固定在 workspace；
  - 有超时（默认 60s）；
  - stdout/stderr 合并并截断；
  - `stdin` 关闭，禁止交互式等待。
  - 后续可替换为容器 / 受限账户执行，接口不变。

## 5. 工具接线（代码结构）

```
backend/app/
  skill_store.py      # SkillSpec + 解析/发现/加载 + 用户私有 CRUD（文件系统）
  workspace.py        # 用户 workspace 路径解析 + 越界校验（safe_join）
  builtin_tools.py    # build_builtin_tools(user_id) -> list[Tool]
  agent.py            # UserRuntime.build: MCP tools + builtin tools 合并注册
  routers/skills.py   # /api/me/skills CRUD + /api/skills（内置只读）
backend/skills_builtin/
  <name>/SKILL.md     # 仓库内置示例 Skill（只读）
```

### 5.1 与 MCP 工具共存

- `UserRuntime.registry = ToolRegistry(mcp_tools + builtin_tools)`。
- 名字冲突策略：**内置工具优先**，同名 MCP 工具改名（加 `mcp_` 前缀）或跳过并记日志。
  MVP 采用「内置优先，MCP 同名跳过」，保证 `file_read` 等永远不会被 MCP 意外覆盖。

### 5.2 Skill L1 清单注入

`UserRuntime.build()` 时读取当前用户可见 Skill，生成清单拼进 system prompt：

```
[Available Skills]
当用户任务与某个 Skill 匹配时，先调用 load_skill 加载它的完整说明，再执行。
- pdf-report: 把数据整理成 PDF 报告
- xlsx-clean: 清洗 Excel 数据
```

清单有字符预算（默认 8000），超预算时逐条退化为「只列名字」。
Skill 变更后调用 `hub.invalidate(user_id)`，下一次请求重建 runtime、刷新清单。

### 5.3 Skill 调用产物

`load_skill` 返回：

```
Skill: <name>
Base directory: <绝对路径>

<SKILL.md 正文，${SKILL_DIR} 已替换为 Base directory>
```

正文过大时由 `ToolRegistry`/上层按需截断；MVP 直接返回全文（多数 Skill 只有几 KB）。

## 6. HTTP API（用户 Skill 管理）

全前缀 `/api`，除内置列表外均需登录，按 `user_id` 隔离。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/me/skills` | 当前用户可见 Skill（内置 + 私有，私有无覆盖内置） |
| POST | `/api/me/skills` | 新建私有 Skill（name / description / content） |
| PATCH | `/api/me/skills/{name}` | 修改私有 Skill（description / content，可改名） |
| DELETE | `/api/me/skills/{name}` | 删除私有 Skill |
| GET | `/api/skills` | 仅内置 Skill 列表（只读） |

- 请求体用 `content` 表示 SKILL.md 正文（不含 frontmatter，服务端拼接 frontmatter 写入）；
  也接受完整 `document`（含 frontmatter）以兼容直接粘贴整份文件。
- 返回字段：`name / description / source(builtin|user) / updated_at / chars / model_invocable`。
- 非法的 skill name（含路径分隔符、`..`、非法字符）→ 400。
- 用户删除内置 Skill → 405/404（内置只读）。

## 7. 前端

`SettingsModal` 从两个 tab 扩展到三个：`我的 APIKey / 我的 MCP / 我的 Skills`。

- Skill 列表区分「内置」「我的」，展示描述与字符数。
- 新建/编辑私有 Skill：name、description、content 三个字段。
- 删除私有 Skill；内置 Skill 只读（无删除按钮）。
- 保存成功后调用 `onLlmChanged`（复用现有回调，触发 runtime 失效/刷新）。
- 可选增强（本阶段不做）：Composer 的 Skill 选择器（插入 `/skill` 命令）。

## 8. 测试计划

单元测试（`backend/tests/`，无网络）：

1. `parse_skill_markdown`：有/无 frontmatter、缺省 name/description。
2. `safe_join` / Skill 路径解析：`..`、绝对路径、符号链接逃逸被拒。
3. 用户 Skill CRUD 隔离：用户 A 看不到用户 B 的私有 Skill；同名私有覆盖内置。
4. `file_read / file_write / file_patch`：正常读写、越界拒绝、patch 0/多匹配报错。
5. `code_run`：正常执行、超时、非零退出码、输出截断、cwd 越界拒绝。
6. `load_skill`：替换 `${SKILL_DIR}` 与 `$ARGUMENTS`；未知 Skill 返回可读错误。
7. `build_builtin_tools`：schema 合法；与 MCP 同名时内置优先。

集成 / E2E：

- 用 `test / 12345678` 登录，创建私有 Skill，发一条会触发 `load_skill` 的消息，验证
  SSE 里出现 `tool_start: load_skill` 与正确结果。
- 让模型用 `file_write` 写文件、`code_run` 跑 Python 验证，确认 workspace 内产物正确。
- 测试完成后清理临时用户/Skill/workspace 残留。

回归：

- `python -m pytest tests -q` 全绿。
- `npm run build` 通过。
- 原有会话 / MCP / 压缩链路不回归。
