# 停止生成后继续发送导致页面白屏：修复记录

> 日期：2026-11-06  
> 状态：已修复并完成单测、构建与真实 HTTP 回归  
> 影响范围：聊天停止链路、generation 租约、前端 API 错误展示

## 背景与现象

用户在一次生成过程中主动点击“停止”，随后立刻输入新内容并按发送或回车，页面变为空白。浏览器刷新后恢复，但该会话在多次发送时持续收到 `409 Conflict`，直到服务重启才恢复。

## 根因

这是前后端两个缺陷叠加，不是上游 LLM 不稳定：

1. **后端租约未及时收敛**  
   停止接口只设置了内存中的 stop event，真正释放 `session_generations.active` 依赖 SSE 生成器执行到 `finally`。若子代理、工具或流读取退出较慢，旧 generation 会继续占住该会话；下一轮 `acquire_generation()` 命中唯一活跃索引并返回 `409`。

2. **前端把对象直接交给 React 渲染**  
   409 响应的 `detail` 是结构化对象：
   `{error, active_generation_id, hint}`。`api.ts` 直接把 `body.detail` 当作字符串抛出，`App.tsx` 再显示到 JSX 文本节点，React 抛出 `Objects are not valid as a React child`。项目没有 ErrorBoundary，因此整个应用白屏。

## 修复内容

### 后端

`backend/app/routers/chat.py` 的停止接口在返回前显式调用 `team_store.release_generation()`：

- 优先释放请求携带的 `generation_id`；
- 请求未携带时，查询该用户该会话当前 active generation 并释放；
- 不依赖 SSE 生成器的 finally 执行时机，保证下一次发送可以立即取得租约。

SSE 生成器 finally 中的释放仍保留，形成幂等兜底。

### 前端

`frontend/src/api.ts` 新增 `detailText()`，统一把未知错误详情转成可展示字符串：

- 字符串原样使用；
- 数组逐项转换后连接；
- 对象优先提取 `error/message/hint/detail`；
- 无可用字段时回退 JSON 字符串或状态文本。

普通 `request()` 与 SSE `streamMessage()` 两处错误解析均改用该 helper，避免同类对象渲染问题再次白屏。

## 回归测试

新增 `test_stop_endpoint_releases_generation_lease`，断言停止接口显式释放正确的 `(user_id, session_id, generation_id)`。

验证结果：

- 后端：`119 passed, 1 warning`
- 前端：`npx tsc --noEmit` 通过
- 前端：`npm run build` 通过
- 真实 HTTP：
  1. 建立测试会话并启动生成；
  2. 停止接口返回 `200`；
  3. 立即再次发送返回 `200` 并收到 `message_start`；
  4. 第三轮发送仍返回 `200`。

## 未决项与后续建议

- 当前项目尚无 React ErrorBoundary。建议后续增加消息区级错误边界，即使单条 malformed block 也不应白屏整个应用。
- 如果未来改为多实例部署，内存 stop registry 需要替换为跨进程广播；SQLite 租约与幂等释放逻辑仍可保留。
