## 1. 这次真正落地了什么

### 1.1 每用户 A2A 身份

- 每个用户一个 `a2a_agents` 行，`agent_id = ha_` + 16 hex。
- 对外 URL：
  - JSON-RPC endpoint：`/a2a/{agent_id}`
  - AgentCard：`/a2a/{agent_id}/.well-known/agent-card.json`
  - 兼容入口：`GET /a2a/{agent_id}` 也返回同一张卡片（方便把 base URL 当 card URL 的客户端）
- 没有全局可调用的 `/.well-known/agent-card.json`；该路径固定 404，避免变成“总入口”。

### 1.2 每用户 token

- 格式：`hlz_a2a_` + `secrets.token_urlsafe(32)`。
- 数据库只存 SHA-256；UI/API 只在创建时返回一次明文。
- token 字段：`name`、`prefix`、`scopes`、`created_at`、`last_used_at`、`expires_at`、`revoked_at`。
- 支持创建、列表、撤销；UI 在「我的设置 → A2A 接入」。
- 当前 MVP 只接受 `scopes=["chat"]`；其它 scope 创建立即 400。**文件/工具/子 agent scope 还没真正下放到工具策略层**，先不要当成已实现的安全边界。

### 1.3 请求校验（六步）

1. Bearer 存在；否则 401。
2. token 哈希命中；否则 401。
3. 未撤销、未过期；否则 401。
4. `path.agent_id == token.agent_id`；否则 403。
5. 请求体 `tenant`（如果有）等于 path agent_id；否则 403。
6. `contextId`/`taskId` 必须属于该 `user_id + agent_id`；否则 404。

### 1.4 JSON-RPC 方法

已实现：

- `SendMessage`
- `SendStreamingMessage`（SSE）
- `GetTask`
- `ListTasks`
- `CancelTask`
- `SubscribeToTask`（进程内事件回放 + 继续订阅）

**未实现（下一阶段）**：

- push notification 四个方法
- `GetExtendedAgentCard`

AgentCard 当前声明 `"streaming": true`。客户端断开 SSE 不会取消任务；任务由后台
asyncio task 持有，`GetTask`/`SubscribeToTask` 可继续。

### 1.5 任务与会话映射

| A2A | Hlaudz |
| --- | --- |
| `contextId` | `sessions.id` |
| `taskId` | `a2a_tasks.task_id` |
| `messageId` | 幂等键；同 agent + messageId 重复发送返回同一 task |
| `generationId` | `session_generations` lease / RuntimeHub |
| `Artifact` | assistant 最终 `content`（artifactId=`answer`） |
| 终态 | `TASK_STATE_COMPLETED` / `FAILED` / `CANCELED` / `REJECTED` |

- 任务执行复用 `backend/app/routers/chat.py` 的 `_event_stream`，没有复制 agent loop。
- 取消复用现有 `stop_generation` 顺序（协作 stop → ACP 优雅停 → 硬取消 → 子 agent/code_run → 收敛），再取消 A2A 后台任务并落 `CANCELED`。
- 客户端断开不会直接取消任务；任务由后台 asyncio task 持有，`GetTask` 可继续查。

## 5. 明确限制（不要误读为已完成）

1. **push notifications 未实现。** `SendStreamingMessage` / `SubscribeToTask` 已支持；事件日志只在进程内，服务重启后旧任务只能查 `GetTask` 终态，不能回放事件。
2. **工具权限已按 token 档位收口。** `full` / `read_only` / `chat_only` 三档，运行期靠 registry 过滤。
   剩余缺口：MCP 工具无法按能力分类，`read_only` 下**整组不可用**，没有 MCP 级白名单。
3. **并发配额已强制。** `INNER_A2A_MAX_ACTIVE_TASKS_PER_USER`（默认 2）/ `INNER_A2A_MAX_ACTIVE_GLOBAL`（默认 16），
   超限返回 HTTP 429 + `-32010`。仍未做按时间窗的 QPS 速率限制。
4. **单实例假设。** 任务由进程内 asyncio task 持有；多副本需要外置任务/租约。服务重启会把 `SUBMITTED/WORKING` 任务标记为 `FAILED`（`server restart`），不会永久卡住。
5. **非流式默认等待 60s。** 客户端默认 30s 会先超时；请显式 `--timeout 120s`，或使用 `--async` + `task get --wait`。
6. **未做 v0.3 兼容别名。** 只支持 v1.0 的 PascalCase 方法。
7. **AgentCard 是通用卡片。** 不含 username/email/模型配置；这不是“每个用户不同能力”的扩展卡。
8. **审计表已落地。** `a2a_audit` 保留最近 2 万行，只记调用元数据（方法/任务/档位/结果/耗时），不记模型正文；没有导出 UI。

## 8. 2026-11-10 追加：能力档位 / 并发配额 / 审计 / 终态订阅

产品约束：Hlaudz 默认 **full access**，不做逐次人工审批。因此权限模型是**静态的、按 token 的**，
不是按次询问。

### 8.1 能力档位（`backend/app/tool_policy.py`）

| 档位 | 内置工具 | MCP | 子代理编排 | Team | GA (`ga_*`) |
| --- | --- | --- | --- | --- | --- |
| `full`（默认） | 全部 6 个 | ✅ | ✅ | ✅ | ✅ |
| `read_only` | `file_read` / `list_files` / `load_skill` | ❌ | ❌ | ❌ | ❌ |
| `chat_only` | 无 | ❌ | ❌ | ❌ | ❌ |

落点：
- `a2a_tokens.tool_policy` / `a2a_tasks.tool_policy`（老库启动时 `ALTER TABLE` 补列，默认 `full`）；
- `auth.authenticate()` 把档位随身份下发；
- `service._prepare_task()` 写进任务行，`_run_task()` 透传给 `chat._event_stream(tool_policy=...)`；
- `subagent/session.py:build_turn_runtime(..., tool_policy=)` 在装配 registry 时过滤；
- 网页端不传 = `full`，**行为与历史版本完全一致**。

### 8.2 并发配额

`store.count_active()` 统计 `SUBMITTED/WORKING`，`service._enforce_quota()` 在**新建任务前**拦截；
幂等重放（同 `messageId`）先返回已有任务，不触发配额。

### 8.3 审计

`a2a_audit`：`ts / user_id / agent_id / token_id / method / task_id / tool_policy / outcome / detail / latency_ms`，
超过 2 万行自动裁剪。`router._audit()` 是旁路，写失败不影响调用结果。

### 8.4 终态订阅

删除 `router.py` 里对终态任务抛 `-32004` 的拦截，改由 `service.stream_row()` 的终态分支收尾：
`task` → 最终 artifact → 终态 status → 关流。重启被标 `FAILED` 的任务同样走这条路径。
