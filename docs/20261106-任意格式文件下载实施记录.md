## 2. API 契约（新增）

```http
GET  /api/me/workspace-file?path=<路径>[&inline=1]
GET  /api/me/workspace-files?path=&depth=2&limit=500[&include_hidden=1]
POST /api/me/workspace-zip   {"paths": ["reports/q3.docx", ...]}
```

- 单文件：默认 `Content-Disposition: attachment`；中文名走 `filename*=utf-8''`；`nosniff`；
  未知类型 `application/octet-stream`；`Range` 请求返回 206（Starlette 1.10 内置）；上限 200MB（`WORKSPACE_MAX_DOWNLOAD_MB`）。
- `inline=1` 仅白名单（text/plain、text/markdown、text/csv、application/json、application/pdf、application/yaml），否则 415。
- 列表：目录优先排序，`.subagents` 默认返回并标记 `hidden`，普通点文件默认隐藏，`truncated` 提示截断。
- 打包：≤100 个 / ≤500MB（`WORKSPACE_MAX_ZIP_FILES` / `WORKSPACE_MAX_ZIP_MB`），先全量校验再打包，条目名去重去 `..`。
- 错误：400 空路径/参数、403 越界或软链逃逸、404 不存在、413 超限、415 内联类型不支持、401 未登录。

## 3. 安全边界

1. 只解析当前用户 `backend/data/workspaces/<user_id>/`，不开放 skills 目录；
2. `normalize` + `resolve()` + 包含关系校验，阻断 `..`、绝对路径越界、软链逃逸；
3. 非白名单一律附件下载，`X-Content-Type-Options: nosniff`，HTML/SVG 不会以页面形式执行；
4. zip 条目名剥离 `/`、`..`，重名自动追加序号；
5. 列表跳过软链，不跟随；隐藏文件默认不展示。

### 4.4 复测：图片链接曾经「点开新标签页」（2026-11-06 修复）

现象：模型输出 `[📥 随笔_关于时间_配图.png](随笔_关于时间_配图.png)` 时，对话里只有普通文字链接，
点击会新开标签页并落到 SPA 的 `index.html`，不像文档链接那样出现下载胶囊。

根因（`Markdown.tsx` 的 `a` 渲染分支）：

1. 条件写成 `isWorkspaceLocal(raw) && !isImagePath(raw)`，**图片链接被显式排除**在 `FileChip` 之外；
2. 落到普通 `<a target="_blank">` 分支后，相对路径被 `safeUrl` 补成 `http://host/随笔...png`，
   在 SPA 下命中前端路由（`index.html`），既不是图片预览也不是下载。

修复：

- 本地路径（含图片）统一渲染 `FileChip`；内联预览仍由 `![alt](path)` / `<img>` 走 `MarkdownImage`；
- `fileKind` 新增 `img` 类型（徽标 `IMG`）+ 对应配色，图片胶囊与文档胶囊视觉一致；
- 顺带修复：模型把中文文件名写成 URL 编码（`reports/%E5%AD%A3...docx`）时，`workspacePathOf`
  现在解码一次并去掉查询/锚点，否则后端找不到文件。

验证（Chrome，实测）：

- 该会话渲染出 `IMG 📥 随笔_关于时间_配图.png ↓` 胶囊，点击后**未新开标签页**，网络记录
  `GET /api/me/workspace-file?path=随笔_关于时间_配图.png → 200`，无 `.file-chip-error`；
- 文档胶囊的 aria-label 由编码串恢复为 `季度报告-2026Q3.docx`，点击后
  `GET /api/me/workspace-file?path=reports/季度报告-2026Q3.docx → 200`，同样不新开标签页。
