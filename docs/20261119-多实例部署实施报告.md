## 1. 五个必须修的东西（不修就是真事故）

| # | 进程内状态 | 多实例下会发生什么 | 修法 |
| --- | --- | --- | --- |
| 1 | 启动清扫沙箱容器 | 新实例把**另一个实例正在用**的容器删掉 | leader 租约 + 存活实例集合 |
| 2 | `recover_stale_runtime()` | 新实例把**另一个实例正在跑**的 generation 标 stale | 每行记 owner，只清已死的 |
| 3 | `runtime._stop_events` | 在 B 点停止，生成在 A 上，停不掉 | Redis 标记 + 本地订阅协程 |
| 4 | `steer_queue._queues` | 插话排在 B，生成在 A，消息丢 | Redis list + 后台泵 |
| 5 | `pg_advisory_xact_lock(固定键)` | 所有队的写事务排成一队 | 按 team/generation 分键 |

## 2. 协调层结构

```
app/cluster/
├── config.py      环境变量与范围校验
├── client.py      Redis 客户端（按 event loop 缓存）
├── lock.py        分布式锁（SET NX PX + Lua 释放 + 自动续约）
├── leader.py      leader election（租约 + ±2s 防惊群）
├── instances.py   本机存活实例登记（心跳）
├── stopsignal.py  跨实例停止信号
└── steerbus.py    跨实例插话队列
```

### 铁律：没有 Redis 必须照常工作

`HLZ_REDIS_URL` 不设时：
- `distributed_lock()` 退化成进程内 `asyncio.Lock`
- `is_leader` 恒为 `True`（单实例本来就是唯一实例）
- `live_owners()` 返回空集合，清扫退化成「按机器名清本机全部」
- `stopsignal` / `steerbus` 全部空操作

这就是为什么 1283 条现有测试一条都没改、全绿。

## 3. 分布式锁：三个必须做对的地方

### 3.1 释放必须校验持有者

```python
# 错的：A 的锁过期了、B 拿到锁，A 的 finally 把 B 的锁删了
await redis.delete(key)

# 对的：Lua 原子地「值等于我的 token 才删」
if redis.call('get', KEYS[1]) == ARGV[1] then
    return redis.call('del', KEYS[1])
end
```

反向确认做了这条：把 Lua 换成 `DELETE`，
`test_lock_release_does_not_steal_foreign_lock` 精确变红。

### 3.2 必须有续约

业务事务可能比租期长。续约间隔 = `ttl/3`，且续约时同样校验 token
（否则会把别人的锁续上）。

### 3.3 丢锁要能感知

续约发现锁不属于自己时，`LockHandle.alive` 置 `False`，业务代码有机会放弃。

## 4. leader election：租约 + 防惊群

```python
# 租约到期那一瞬间，所有 follower 会同时来抢
sleep_s = refresh + random.uniform(-2.0, 2.0)   # ±2s 抖动（LibreChat 同法）
```

回调式 `on_become_leader(key, fn)`，同 key 只执行一次 ——
避免调用方把「一次性动作」写成「每 tick 都跑」。

## 5. 分锁：实测 4.2 倍

之前 6 处 `BEGIN IMMEDIATE` 共用一把固定 advisory lock。改成按 scope 分键：

```sql
BEGIN IMMEDIATE team:team_abc     -- 不同队拿不同的锁
BEGIN IMMEDIATE gen:u1:s1:g1      -- generation 收敛按 gen 分
BEGIN IMMEDIATE                    -- recover_stale_runtime 扫全库，仍全局
```

**为什么不用 Python `hash()` 算键**：它受 `PYTHONHASHSEED` 随机化，
跨进程不稳定。两个实例会以为在锁不同的东西 —— 比不锁更危险。
用 `blake2b` 取 8 字节折成 bigint。

实测（16 并发 × 20 次 `emit_event`）：

| 场景 | 全局锁 | 分锁 | 无锁（会错） |
| --- | --- | --- | --- |
| 各写各的队 | 195 op/s | **826 op/s** | 818 op/s（234 个主键冲突） |
| 全部同一个队 | 172 op/s | 192 op/s | 655 op/s（必然冲突） |

「各写各的队」分锁已接近无锁上限 —— 锁的开销基本消失。
「全部同一个队」分锁与全局锁一致 —— 正确性没有让步。

## 6. 容器清扫：三层保护

```
t=0  实例 A 启动，建容器（owner = host:111）
t=5  实例 B 启动，清扫 same_machine
     -> 只看机器名的话，A 的容器会被当残留删掉
```

三层逐级收窄：

1. `all_owners=True`：运维手动清场，无视一切
2. `same_machine=True` + `live_owners`：清本机所有**已死**实例的
3. 都不传：只清本进程自己的（最安全）

`live_owners` 来自 Redis 有序集合（score = 心跳 ms，90s 过期，30s 刷新）。

**启动顺序很关键**：`main.py` 里必须**先登记本实例、再启动沙箱** ——
反了的话，本实例会被自己的清扫逻辑当成死实例。

## 7. 跨实例停止

```
浏览器 -> LB -> 实例 B  POST /stop
                  B: 写 SET hlz:stop:<u>:<s>:<g> 1 PX 300s
              生成跑在实例 A
                  A: StopWatcher 轮询到 -> set 本地 Event -> 循环退出
```

**为什么不能直接查 Redis**：`stopped()` 在流式回调里每收到一个 token
调一次，必须同步零开销。

**为什么用轮询不用 pubsub**：pubsub 重连会丢消息，而「停止」丢了就是
用户点了没反应。1s 轮询的延迟用户感知不到。

## 8. 跨实例插话

同理，`drain()` 在**同步**注入回调里被调。所以：

- push 侧写 `RPUSH hlz:steer:<u>:<s>:<g>`（不写本地，避免重复入队）
- 生成侧起 `SteerPump` 每 200ms 搬一次进本地队列
- `drain()` 一字未改

## 9. 怎么部署

见 `backend/deploy/docker-compose.yml`。

```bash
cd backend
docker compose -f deploy/docker-compose.yml up -d --scale app=3
```

必须设置的环境变量：

| 变量 | 说明 |
| --- | --- |
| `HLZ_DB_URL` | PostgreSQL 连接串 |
| `HLZ_REDIS_URL` | Redis 连接串（**不设就退化成单实例**） |
| `HLZ_INSTANCE_ID` | 实例标识（容器部署用 pod name） |

可选调优：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `HLZ_LOCK_TTL_MS` | 10000 | 分布式锁租期 |
| `HLZ_LOCK_WAIT_MS` | 5000 | 等锁上限，超时抛 `LockTimeout` |
| `HLZ_LEADER_TTL_MS` | 25000 | leader 租期 |
| `HLZ_LEADER_REFRESH_MS` | 8333 | leader 续约间隔（< ttl） |
| `HLZ_REDIS_PREFIX` | `hlz` | 共用 Redis 时的命名空间 |

## 10. 已知限制

| 限制 | 影响 | 何时处理 |
| --- | --- | --- |
| 沙箱容器只能同机共享 | 多机时每台机器各管自己的容器，没有跨机复用一个容器 | 需要时再设计 |
| 停止/插话有 1s / 200ms 轮询延迟 | 用户感知不到，但不是即时 | 高频场景可换 pubsub + 兜底轮询 |
| 未做实例间任务迁移 | 实例挂了，它正在跑的生成会断（客户端需重试） | 引入 job queue 时一起做 |
| `recover_stale_runtime` 的 `team_runs` 仍全局收敛 | `team_runs` 没有 owner 列 | 有实际需要再加 |
| 未压测 > 100 并发 | 目前按单机单进程验证 | 上线前压测 |
| Windows 上无法验证优雅退出注销 | `taskkill`/`send_signal` 都不跑 lifespan shutdown | 平台限制；靠心跳过期兜底 |
