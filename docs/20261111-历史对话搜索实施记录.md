# 20261111-历史对话搜索（正文检索 + 定位跳转）

> 状态：**已实施并三层验证通过** ｜ 日期：2026-11-11 ｜ 关联：侧栏「搜索 / Ctrl+Shift+K」

## 1. 背景

侧栏的「搜索」按钮自 `ba7b617`（2026-11-10，对标 claude.ai 改版）起就是
`disabled title="搜索（未实现）"` 的占位符，快捷键 `Ctrl Shift K` 也只是文字，
全项目没有任何 `keydown` 监听。

`SessionBrowser`（「查看全部会话」）虽带搜索框，但只做
`s.title.includes(q)` —— 只搜标题、只搜已加载的那 100 条，且入口藏在侧栏底部。

用户要的是：**打开面板搜索历史对话正文，命中关键词后点击直接打开该对话**。

### 2.1 后端

```
GET /api/sessions/search?q=<关键词>&limit=20&session_id=<可选>
→ { query, hits: [...], has_more, elapsed_ms }

hit = { message_id, session_id, session_title, role,
        snippet, match_offset, match_length,
        created_at, session_updated_at }
```

三个关键决策：

1. **用户隔离靠 `JOIN sessions`**。`messages` 表**没有 `user_id` 列**，任何绕过
   `JOIN sessions ... WHERE s.user_id=?` 的写法都会跨用户泄漏。这是本功能最大的风险点。
2. **LIKE 通配符转义**。`%` / `_` 先转义成字面量再进 LIKE（`ESCAPE '\'`），
   否则用户搜 `50%` 会把「500 次」也命中。
3. **不搜 `system` 消息**。system 是平台注入的，用户看不见它，命中它会让用户
   搜到一段对话里根本没有的文本。

`match_offset` 是**片段内**的字符下标（不是全文下标），片段两端被裁时加 `…`
并把 offset 相应右移；前端据此精确高亮。取不到原样关键词时返回 `-1`，前端不高亮
但照常显示正文——宁可少个高亮，也不要吞内容。

### 2.2 前端

- **`SessionSearch`**：220 ms 防抖；每次搜索自增 `seqRef` 丢弃迟到响应（快速连打时
  后发先至会把结果覆盖错）；↑↓ 选、Enter 开、Esc 关，全程不离开输入框。
- **快捷键**：`App.tsx` 全局监听 `Ctrl/Cmd+Shift+K`，侧栏按钮同时接上 `onOpenSearch`。
- **定位跳转**：点结果 → `setActiveId` + 记 `{id, nonce}` → `MessageList` 用
  `querySelector('[data-msg-id]')` 找到节点后 `scrollIntoView({block:'center'})`，
  并加 `.msg-flash` 一次性高亮 1.6 s。
  - 定位前**必须先关掉 `followRef.current`**，否则下一帧的贴底会把它拽回底部。
  - nonce 用单调计数器而非 `Date.now()`：同毫秒两次点击会被去重掉。
  - 副作用依赖 `messages`：切会话后历史异步加载，目标节点要等它到达才存在。
- **`SessionBrowser` 的搜索框**改了提示文案，避免用户以为它也能搜正文。

## 3.5 演示前的深度加固（同日追加）

首版通过后，为「明天给别人演示」追加了一轮攻击性测试，**抓到 4 个真实白屏缺陷**。

### 3.5.1 白屏事故：4 个真实缺陷

项目**原本没有任何 `ErrorBoundary`**，所以任何一次渲染期异常都等于整页空白。
用 Playwright 拦截搜索响应、伪造 10 种畸形数据，其中 4 种直接白屏：

| 畸形响应 | 崩溃信息 |
|---|---|
| `hits` 不是数组（null） | `Cannot read properties of null (reading 'length')` |
| `hits` 是对象 | `a.map is not a function` |
| `snippet` 为 null | `Cannot read properties of null (reading 'length')` |
| `hits` 里含 null 元素 | `Cannot read properties of null (reading 'role')` |

### 3.5.2 修复：两层防护，各自独立

1. **数据入口 `normalizeResult()` / `normalizeHit()`**（`SessionSearch.tsx`）
   —— 不信任响应形状，逐字段兜底；越界 offset 降级为「不高亮」而非报错。
2. **`ErrorBoundary`**（`components/ErrorBoundary.tsx`，新增）
   —— `main.tsx` 最外层兜底 + 搜索面板单独一层；降级成可恢复面板（重试 / 刷新）。

**两层都做反向确认**：

- 移除 `normalize` 后，10 种畸形响应**仍然不白屏** → 证明 ErrorBoundary 独立生效；
- 往渲染路径注入 `throw new Error('TEMP_RENDER_CRASH')` → 降级面板出现
  （文案「搜索面板出现问题」）、侧栏与输入框仍在、点「重试」恢复 → 证明 ErrorBoundary 真的兜住。

## 4. 已知限制

- **用 `LIKE` 全表扫描，没上 FTS5**。当前 2113 条消息 / 58 万字符，实测 4–15 ms；
  FTS5 可用但不引入——索引同步（增删改消息都要写）比省下的毫秒贵。
  消息量涨到十万级再换，届时只需替换 `search_messages` 的 SQL。
- **只搜 `messages` 表，不搜 `session_history`**。后者是上下文的完整快照，
  同一句话会出现两次，搜它会重复命中。
- **片段固定 40 + 120 字符窗口**，长消息只看得到命中点附近。
- 搜索面板**不跨会话显示上下文**，也不支持按时间/角色过滤。
- **生成中不能跨会话跳转**：`selectSession` 本来就在 `streaming` 时拦截切换，
  搜索跳转复用了同一守卫（同会话内定位不受影响，那只是滚动）。
  若强行绕过，流结束时按原 sid 的 `loadMessages` 会把旧会话的消息写进新会话视图。
- 生产库里的真实账号密码不可知，L3 用独立测试库 + 新注册账号完成；
  未在真实用户的账号上跑（无权登录）。
