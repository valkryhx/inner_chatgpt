### 2.1 S15 是本轮的核心新增

原 e2e 场景矩阵里**没有 GA 用例**——S1/S5 测的是 P2 内部子代理，与 ACP 无关。
本轮新增 S15（`backend/tests/e2e/run.py`），关键设计：

- 提示词**显式点名**「用外部 GenericAgent（`ga_spawn` 工具，不是 `spawn_agent`）」，
  否则模型会优先用内部子代理，测到的就不是 ACP；
- `expect_tools: ["ga_spawn"]` + `forbid_tools: ["spawn_agent"]` —— 双向断言；
- 塞哨兵 `SENTINEL=244c87`，要求 GA 原样复述。

## 3. 假绿三问（skill §6.7）

### 问 1：断言是「发生」还是「结果对」？

不只断言工具被调用，还核对了**最终助手消息里 GA 的原始答复**：

```text
23 × 17 = 391

SENTINEL=244c87
```

模型还主动做了核对：计算 391 正确、哨兵逐字符一致、GA 工具调用次数 0（纯心算）。
`messages.json` 里哨兵出现 7 次（含 GA 答复引用与模型核对），确认是真的传到了 GA 又传回来。

### 问 2：有没有负向断言？

有。S15 的 `forbid_tools: ["spawn_agent"]` 确认模型没有退回内部子代理；
同时 `ga_spawn` 必须出现（若 ACP 未启用、5 个工具没注册，场景会因缺工具直接失败）。

S0 负对照的 `forbid_tools` 也补上了 `ga_spawn`，确认日常问答不会误触发 GA。

### 问 3：关键终态查了两处吗？

查了 SSE 事件 + 数据库：

```text
sse_missing_events: { db_total: 2, sse_total: 1, missing: [], missing_count: 0 }
zombie_running: []
checks_failed: []
done: complete
```

四个 runId 全部 `missing_count=0`、`zombie_running=[]`、`checks_failed=[]`。
唯一的 `benign_missing` 是 `team_end`（预期内，skill 已注明）。

## 4. 发现的一个配置陷阱（已规避）

初次把新场景写成 `S14`，跑出来却是 `wait-nonblocking`——因为
`backend/tests/e2e/run.py` 的 `cases()` 里**已经有 S14**，Python 字典后定义的键
覆盖先定义的，静默生效。

**教训**：给 e2e 场景表加新用例前先 `grep '"S<N>"'` 确认编号未被占用。
已改用 `S15` 并验证 `cases()['S15']['name'] == 'acp-genericagent'`。
