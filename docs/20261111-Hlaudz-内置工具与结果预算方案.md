## 0. 一句话结论

Hlaudz 现在让模型用 `code_run` 做一切「找文件 / 找内容」的活，而 `code_run` 的输出
是**20,000 字符头部硬截断、不落盘、退出码无语义**。这三件事叠加的后果是：
搜索类任务要么搜不全，要么把 tail 丢掉，要么把 `grep` 无匹配（exit 1）当成报错重试。

本方案补齐 5 项：`file_glob`、`file_grep`、统一结果预算、退出码语义、写前必读。

## 3. `file_glob` 与 `file_grep`

### 3.1 为什么分两个工具

CC 的设计里 Glob 与 Grep 的 `maxResultSizeChars` 是 100,000 与 20,000——相差 5 倍。
「只想要文件名」和「要内容行」是两种载荷，合并会让 glob 也背上内容行的预算。

### 3.2 `file_glob`

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `pattern` | string | 必填 | glob 模式，如 `**/*.py` |
| `path` | string | 省略 | 搜索根，省略用 workspace 根 |

行为：

- 结果只回**路径**，一行一个，workspace 相对路径；
- 硬上限 **100** 个文件；截断时明确写 `showing first 100 of N matches`；
- 默认排除：`.git/`、`node_modules/`、`__pycache__/`、`.venv/`、`dist/`、`build/`、
  以及用户 workspace 之外的路径（沿用 `safe_read_path`）；
- 目录不存在 / 无匹配 → 返回 `ok=true` + 空列表 + 一句说明（**不是错误**）。

### 3.3 `file_grep`

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `pattern` | string | 必填 | 正则 |
| `path` | string | 省略 | 搜索根 |
| `glob` | string | 省略 | 文件过滤，如 `*.py` |
| `output_mode` | enum | `content` | `content` / `files_with_matches` / `count` |
| `ignore_case` | bool | false | `-i` |
| `context` | int | 0 | 前后各 N 行，最大 20 |
| `head_limit` | int | 250 | 最多返回多少条/行 |

实现：

- 优先调 `rg`：`shutil.which("rg")`，找不到再试 Git 安装目录
  （`<git>/usr/bin/rg` / `<git>/mingw64/bin/rg`）；
- rg 不存在 → 回退纯 Python（`os.walk` + `re`），行为与 rg 对齐；
- 结果上限 20,000 字符走**预算层**（见 §4），不是在这里硬截断；
- `pattern` 非法正则 → 返回 `ok=false` + 明确的正则错误位置（不带 traceback）。

### 3.4 工具描述（给模型看的）

两个描述都必须写成「什么时候用它」，而不只是「它是什么」：

```
file_glob: 按文件名/路径模式查找文件。找"哪些文件叫 xxx"、"这个项目有哪些 yyy 类型文件"时用它，
           不要用 code_run 跑 find/ls。
file_grep: 在文件内容里搜索。找"哪处代码引用了 X"、"有哪些 TODO"时用它；
           先用 output_mode=files_with_matches 收敛范围，再用 context 看上下文。
           不要用 code_run 跑 grep/rg。
```

这条与 §6 的提示词改动互为保险：**schema 描述是每轮都在上下文里的，比系统提示词更靠近决策点**。

## 4. 统一结果预算层（`backend/app/tool_budget.py`）

### 4.1 三层语义

与 GA / CC 一致的「超限 → 落盘 → 头尾预览 → 可回读」：

```
原始输出 N 字符
  ├─ N ≤ per-tool 上限          → 原样返回
  ├─ 上限 < N ≤ PERSIST_LIMIT   → 落盘到 workspace/.hlaudz/tool_results/<uuid>.txt
  │                                返回 头 2,000 + 尾 2,000 + 中间省略量 + 文件路径
  └─ N > PERSIST_LIMIT          → 同上，但只落盘前 PERSIST_LIMIT，并注明"已截断"
```

常量：

| 常量 | 值 | 来源 |
| --- | --- | --- |
| `DEFAULT_MAX_RESULT_CHARS` | 50,000 | CC / GA 对齐 |
| `DEFAULT_PREVIEW_CHARS` | 2,000 | CC / GA 对齐 |
| `PERSIST_LIMIT_CHARS` | 500,000 | CC / GA 对齐 |

per-tool 上限：

| 工具 | 上限 | 依据 |
| --- | --- | --- |
| `code_run` | 30,000（硬上限 150,000） | CC Bash 默认 |
| `file_glob` | 100,000 | CC Glob |
| `file_grep` | 20,000 | CC Grep |
| `file_read` | 走全局 50,000 | CC Read |
| `list_files` / `load_skill` | 走全局 50,000 | — |

### 4.2 环境变量

沿用现有风格，全部可覆盖：

```
HLZ_TOOL_RESULT_MAX_CHARS=50000
HLZ_TOOL_RESULT_PREVIEW_CHARS=2000
HLZ_TOOL_RESULT_PERSIST_LIMIT=500000
HLZ_TOOL_RESULT_PERSIST_DIR=   # 默认 <workspace>/.hlaudz/tool_results
```

### 4.3 落盘契约

- 路径必须在用户 workspace 内（与 `safe_read_path` 同一套边界）；
- 落盘失败（磁盘满 / 只读）→ 降级为「头 4,000 + 尾 4,000 + 明确写 not persisted」；
- 返回体尾部固定一行：

```
[full output: 1,234,567 chars → workspace/.hlaudz/tool_results/3f2a.txt (read with file_read)]
```

模型看到这一行就知道下一步该怎么拿全文，不需要猜。

### 4.4 与内部截断的分工

- **内部截断**负责性能：不要把 500 MB 文件读进内存；
- **预算层**负责上下文安全：读了，但只给模型看这么多。

两者都要保留。但 `file_read` 现有的 `_truncate` 二次截断要去掉，
否则模型看到的是「被截断的截断」，省略量也算不准。

## 5. 退出码语义（`backend/app/exit_codes.py`）

`classify_exit_code(tool_name, command, exit_code) -> "success" | "error" | "informational"`

| 命令 | 非零含义 | 归类 |
| --- | --- | --- |
| `grep` / `rg` | 1 = 无匹配 | informational |
| `diff` | 1 = 有差异 | informational |
| `test` / `[` | 1 = 判断为假 | informational |
| `find` | 1 = 部分目录不可读 | informational |
| `git diff --exit-code` | 1 = 有差异 | informational |
| 其余 | ≥1 = 真错误 | error |

`code_run` 返回体：

```
[code_run bash] exit=1 (grep: no matches) cwd=...
```

只对 shell 类型生效；`code_type=python` 保持 `exit==0` 语义（脚本返回值无公认约定）。

## 6. 写前必读（`backend/app/read_registry.py`）

### 6.1 数据结构

```python
@dataclass(frozen=True)
class ReadRecord:
    path: str        # realpath
    mtime_ns: int
    size: int
    complete: bool   # 是否读到文件末尾
```

在 `_read_impl` 成功返回时登记；`complete=True` 的判定：
`start == 1 and 没有 keyword 过滤 and 返回行数 < count`（即确实读到了 EOF），
或显式读取区间覆盖 `[1, total_lines]`。

### 6.2 放行规则

| 情况 | 结果 |
| --- | --- |
| 从未读过该路径 | **拒绝**：`请先 file_read <path>，让写入基于当前内容` |
| 读过但 `complete=False` | **拒绝**：`只读了片段，请读完整文件` |
| 读过且 mtime/size 未变 | 放行 |
| mtime 变了但内容 sha256 相同 | 放行（刷新记录） |
| mtime 变了且内容不同 | **拒绝**：`文件已被外部修改，请重新读` |
| 新文件（不存在） | 放行 |
| `file_write(mode="append"/"prepend")` | 放行（追加不需要旧内容） |

`file_patch` 同样适用——它比 `file_write` 更依赖「看到的 old_content 是当前的」。

### 6.3 记录的生命周期

- 按 `(user_id, session_id, generation_id)` 隔离，回合结束即释放；
- 不跨会话复用（避免「上次读过」被当成「这次读过」）；
- 单会话记录上限 500 条，超出淘汰最旧。

## 7. 只读工具并行

`agent_loop.py` 当前逐个执行工具调用。改为：

```python
PARALLEL_SAFE_TOOLS = frozenset({"file_read", "file_glob", "file_grep", "list_files"})
```

- 相邻的只读调用合并成一批，`asyncio.gather` 并发；
- 写类工具 / `code_run` / MCP 一律串行；
- 并发数上限 4，避免 100 个 glob 打满磁盘。

**必须先确认**：`_read_impl` / `file_search` 不写任何共享状态。
写前必读的登记是「读时登记」，并发登记要加锁或用 `dict` 原子赋值（GIL 下安全）。

## 10. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 写前必读会拒绝一批现有用法 | 错误文案给出可直接照做的下一步；先只对 `file_patch` 强制，观察一周再对 `file_write` 强制 |
| 预算层改所有工具输出，可能影响前端渲染 | 落盘路径放在返回体尾部，前端按 Markdown 文本渲染不解析 |
| 并行执行引入竞态 | 只放只读工具；并发上限 4；写前登记用原子 dict |
| rg 在 Windows 路径不一致 | `shutil.which` + Git 安装目录双探测；测试里 monkeypatch 覆盖回退 |
| 20K → 30K 让单轮上下文变大 | 预算层同时负责落盘，实际进入上下文的是预览 + 路径，不是全文 |

## 11. 明确不做

- 不做 `NotebookEdit`（Hlaudz 不处理 Jupyter）；
- 不做 `ToolSearch` 渐进式披露（工具总数 < 30，全量注入成本可接受）；
- 不做独立 `bash` 工具（`code_run` 已覆盖，拆开只会让模型二选一犹豫）；
- 不改 `safe_read_path` / `write_root_for` 的边界实现（已有测试覆盖，
  越界行为在本方案里只被复用，不被改动）。
