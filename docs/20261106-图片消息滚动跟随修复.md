# 图片消息滚动跟随修复

> 日期：2026-11-06 · 状态：已完成 · 范围：前端消息列表滚动

## 背景

消息中出现图片后，后续流式文本无法稳定跟随到底部，页面会反复停在图片附近，影响长回答阅读。

## 根因

1. 原实现只要 `messages` 或 `streaming` 变化就无条件调用 `scrollIntoView({ behavior: 'smooth' })`，每个流式 token 都会重复触发平滑滚动。
2. workspace 图片通过鉴权 fetch 异步加载，占位符切换到真实图片时高度突增；浏览器 scroll anchoring 会把视口锚定在图片附近。
3. 普通 `useEffect` 在新 DOM 已提交、但图片尺寸尚未稳定时执行贴底，随后高度继续增长，导致“滚了又被顶回去”。

## 修复方案

- `MessageList` 改为显式“底部吸附”状态机：
  - 仅当用户位于底部附近时跟随新内容；
  - 用户滚轮上翻立即取消跟随；
  - 用户重新回到底部后恢复跟随；
  - 切换会话时重置为跟随底部。
- 流式阶段使用瞬时贴底，不再用平滑滚动追赶 token。
- 使用 `useLayoutEffect` 在 DOM 提交后、绘制前贴底。
- 使用 `ResizeObserver + MutationObserver` 捕获图片、图表及 Markdown 节点的异步尺寸变化。
- `MarkdownImage` 加载完成/失败时通知消息列表做一次兜底校准。
- workspace 图片增加内存 blob URL 缓存；同一路径命中缓存时首帧直接显示，
  避免 React 流式重挂载时图片瞬间退回占位符、造成滚动高度收缩再展开。
- `.messages` 设置 `overflow-anchor: none`，避免浏览器自动锚定图片。

## 验证

真实浏览器回归（1440×900，后端 `http://127.0.0.1:8000`）：

1. 综合 DOM 回归 11 项全部通过：桌面端历史多图、用户上翻、尺寸增长、
   回到底部、会话切换、390px 移动端、图片失败、控制台错误。
2. 受控多图流式压力测试连续运行 3 轮，每轮 7 项全部通过：
   - 图片出现后、多图连续插入期间距底部始终 `0`；
   - 流式中途用户上翻后约 24–37 次采样位置不变；
   - 最终 3 张图片和 2000+ 字后续文本完整；
   - 用户回到底部后恢复正常跟随；
   - 浏览器控制台无错误。
3. 追踪确认图片组件重挂载不再出现 `img -> placeholder -> img` 的高度塌缩。
4. `npm run build` 通过。
