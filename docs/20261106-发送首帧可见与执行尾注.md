# 发送首帧可见与执行尾注

> 日期：2026-11-06 · 状态：已完成 · 范围：聊天发送体验、轮次状态提示

## 背景

用户反馈：

1. 发送输入后，新用户消息没有第一时间出现在视口，需要手动下拉才能确认输入成功。
2. Agent 本轮是否结束不够明显，希望看到轻量的耗时尾注和“可以继续输入”提示。

## 根因

- 消息列表使用“用户是否接近底部”的滚动跟随状态。用户提交前如果正在上翻历史，
  `followRef=false` 会继续生效；即使消息已经乐观插入，视口仍停在历史位置。
- 服务端历史刷新会替换消息对象，前端本地计时字段会丢失；停止快照也可能短暂覆盖
  本地结束状态，导致尾部停留在 `Working`。

## 实现

- `MessageList` 新增 `sendPulse`：每次提交都视为明确的“查看最新消息”意图，
  `useLayoutEffect` 立即恢复跟随并在 DOM 提交后、绘制前贴底。
- `Message` 增加仅前端使用的 `run_started_at` / `run_finished_at`。
- `App` 增加 `runTimesRef`，按 message id 保存本轮起止时间；在 `message_start`
  改 ID、历史刷新、停止快照替换时迁移/合并计时，避免 Working 卡死或计时丢失。
- 新增 `RunFooter`：
  - 执行中：`Working · 1.2s`（每 100ms 更新）
  - 完成：`Worked · 4.1s · 可以继续输入`
  - 停止：`Stopped · 2.3s`
  - 失败：`Failed · ...`
- 移除旧的重复“已停止”文本，停止状态统一由 RunFooter 表达。

## 验证

真实浏览器回归：

1. 历史会话上翻后提交：120ms 内新用户消息可见，距底部 `0`。
2. 新会话首条提交：首帧可见。
3. 执行中显示 `Working` 和实时耗时。
4. 完成后显示 `Worked · Xs · 可以继续输入`。
5. 停止后显示 `Stopped · Xs`。
6. 移动端 390px：首帧可见、无横向溢出、尾部正常。
7. 图片历史、上翻、动态增高、回到底部回归通过。
8. `npm run build` 通过。
