## 0. 结论

压测抓到 **1 个真实功能缺陷**，已修复并验证：

> **teammate 产生的事件永远进不了 lead 的 SSE 流。**
> `TeamHost.events_since()` 只推进游标、不发布事件，导致前端 team 面板
> 看到的是「任务一直 pending / in_progress」，而数据库里其实已经全部完成。

规模场景的定量证据：13 个任务全部 `completed`（DB），但 SSE 只收到 16/43 条事件，
缺 27 条（其中 20 条 `task_updated`）——**面板正确率 30%**。

修复后复跑：SSE 与 DB 完全一致，任务终态检查通过。

## 2. 缺陷：teammate 事件进不了 lead 的 SSE

### 2.1 现象

team 面板上，13 个任务里 11 个显示 `pending`、2 个显示 `in_progress`，**一个都没有变成完成**。
但直接查库：13 个任务全是 `completed`。

### 2.2 根因

```python
# backend/app/team_host.py（修复前）
async def events_since(self, since_seq=0, limit=200):
    rows = await team_store.events_since(self.scope, since_seq, limit)
    for row in rows:
        self._observed_seq = max(self._observed_seq, int(row["event_seq"]))
    return rows           # ← 只推进游标，从不 publish
```

`backend/app/subagent/session.py` 把 lead 的每个 team 工具包了一层：

```python
async def observed(args, _original=original):
    try:
        return await _original(args)
    finally:
        await team_host.events_since(team_host._observed_seq)   # 拉取但不广播
```

于是：

1. teammate 在自己的 `TeamHost` 实例里 `_emit()` 写库（正常）；
2. lead 调用任意 team 工具时拉到这些行；
3. **游标被推高，但事件没有进 SSE buffer**；
4. 下一轮 `events_since` 从新游标开始 → **这些事件永远不再出现**。

「拉取即丢弃」比「不拉取」更糟：不拉取至少还能在下一次全量刷新时补上。

### 2.3 修复

```python
for row in rows:
    self._observed_seq = max(self._observed_seq, int(row.get("event_seq", 0)))
    self._publish_event(row)      # ← 加上这一行
```

### 2.4 测试

新增 `test_events_since_publishes_teammate_events`：

```
teammate scope 写一条 task_updated
→ lead.events_since(0)
→ 断言 sink 收到 1 条且 type == task_updated
```

RED（修复前）：sink 收到 0 条。
GREEN（修复后）：1 条。

## 5. 结论与遗留

### 5.1 这轮压测的价值

- S3 证明超时语义正确（不杀子代理、不重复 spawn）；
- S6 暴露了一个**单测原理上测不到**的缺陷：事件写进了库、游标也推进了，
  只是没广播——只有跑真实链路并用「SSE vs DB」对比才能发现；
- 顺带把 e2e 断言从「工具出现过」升级为「任务终态正确」，
  否则 S6 在修复前也会 PASS（事实上它确实 PASS 了）。

### 5.2 遗留

| 项 | 说明 |
| --- | --- |
| 并发槽位压测 | 尚未跑「同时派 6 个子代理触发 `max_active=4`」的场景 |
| 长时间运行 | 未跑 >10 分钟的单任务（内存/事件环形缓冲表现未知） |
| 跨回合通知 | ✅ 已实现：`subagent_notifications` 表 + 每轮补载（见 P2 记录 §5） |
| `team_end` 的到达时机 | 生成收尾即写，前端是否需要在流关前展示，待 UI 确认 |
