# 前端审美提升设计（Design System v2）

> 一句话摘要：把「什么都是气泡」的聊天壳，重构成「纸面 + 对话流」的克制作业台 —— 取消 assistant 文本气泡、工具调用降级为轻量步骤行、以 Claude 式暖纸底色 + 陶土强调色建立统一设计语言，让产品从「能用的 demo」变成「像样品的工具」。
>
> 日期：2026-11-05 ｜ 状态：设计定稿，待实施 ｜ 参考：`design-taste-frontend`（tasteskill 2.5）、`impeccable`（4.8.0，Operate 模式）

---

## 一、背景与目标

当前前端是 MVP 阶段的产物：功能齐全（会话、流式、工具卡、图表、MCP、Skill、压缩），
但视觉上仍是「聊天 demo 模板」，用户明确反馈「比较丑陋」，且核心症状是 ——
**所有内容一律套气泡**：assistant 的正文、工具调用、思考过程、摘要，全部是同一套圆角矩形。
这不只是好不好看的问题，而是信息层级坍塌：工具的「事件性」和回答的「内容性」被画成了同一种东西。

本次目标不是换皮，而是**重建信息层级与视觉语言**：

1. **取消 assistant 文本气泡**：正文直接落在纸面上（无边框、无底色），靠排版而非容器承载。
2. **工具/思考/摘要降级**：它们是「过程」不是「内容」，应从卡片降为**轻量步骤行**，视觉重量显著低于正文。
3. **建立一套设计系统**：暖纸底 + 陶土强调 + 衬线标题 + 4px 栅格，所有页面（会话、登录、设置）统一。
4. **保留所有契约**：SSE 事件、组件 props、DOM 关键结构（`.msg`/`.bubble` 类名可保留但语义调整），
   不改后端、不改数据格式。

**模式判定（impeccable）**：本产品是 **Operate**（用户来完成任务，不是来看网站）。
Operate 原则是「访客不注意到世界之前就知道东西在哪」——世界只贡献四样：
**字体、配色、密度、一个签名动作**，绝不接管布局与控件。这句话直接约束了本文所有方案：
不搞花哨动效、不搞装饰性插画、控件必须是平台原生的样子。

## 二、现状诊断（逐项对照两套 skill 的检查线）

### 2.1 结构性问题（最要命的三条）

| # | 问题 | 现状 | skill 对照 |
|---|---|---|---|
| S1 | **一切都是气泡** | `.bubble` 同时用于 user 文本、assistant 正文；`.tool-card`、`.reasoning`、`.summary-card` 是另一种圆角框。整屏是同一种形状重复 5 次 | impeccable《Refuse》：「Same-size cards of icon plus heading plus text as the page structure」；tasteskill 规则 3「一层层卡片=懒容器」 |
| S2 | **层级坍塌** | 正文 14px / 工具名 12px / 工具参数 12px，字号只差 2px，靠颜色区分。眼睛无法先读答案、后看过程 | craft-floor《Type》：「obvious scale and weight steps」 |
| S3 | **无定位坐标系** | 页面没有网格，没有统一的纵向节奏；`gap: 6px / 8px / 10px / 12px / 18px` 混用 | craft-floor《Spacing》：「Read the computed values」 |

### 2.2 配色与材质

| # | 问题 | 现状值 | 判断 |
|---|---|---|---|
| C1 | 冷灰底 + 纯白面板 | `--bg:#f5f6f8` / `--panel:#fff` | 典型「SaaS 模板冷白」，无温度、无性格。这是用户说「丑」的第一来源 |
| C2 | 蓝色作为唯一强调 | `--accent:#2563eb`（Tailwind blue-600） | 全站最饱和的颜色是浏览器默认蓝，几乎等于「没设计」 |
| C3 | 用户气泡浅蓝 | `--user-bubble:#e8f0ff` | 与强调色同色系，导致 user 消息是整屏最显眼的东西 —— 权重倒置 |
| C4 | 阴影无层次 | `0 1px 2px rgba(...)` 到处用 | 没有 elevation 体系；且「1px 边框 + 大软阴影」= craft-floor 点名的 **ghost card** |
| C5 | 圆角无标度 | 4/7/8/9/10/12/16/20px 混用 | 没有 radius scale |

## 三、设计方向：暖纸 + 陶土（Warm Paper / Terracotta）

### 3.1 为什么是这个方向

你给的参考 `claude.com` 的配色，我扒了它线上的 CSS token（`_next/static/chunks/98bcbf...css`），
核心是一套**暖灰纸面 + 陶土橙**的系统：

```
gray-050 #faf9f5   gray-100 #f5f4ed   gray-150 #f0eee6   gray-200 #e8e6dc
gray-300 #d1cfc5   gray-500 #87867f   gray-700 #3d3d3a   gray-900 #1a1918
clay     #d97757   clay-hover #c6613f   error #bf4d43
shadow-sm 0 2px 8px #0000000a   ease-out-quart cubic-bezier(.165,.84,.44,1)
```

它的高明之处不在「橙色好看」，而在三点，恰好都能治我们的病：

1. **纸白不是纯白**。`#faf9f5` 带一点黄的暖调，配 `#1a1918` 的墨色，长文阅读不刺眼，
   而且天然把「纯白卡片」衬托成「浮在纸上的一张纸」，层次自然出来。
2. **强调色只有一个，且不常出现**。陶土橙 `#d97757` 只用在主按钮、选中、焦点。
   我们现在的蓝是「到处都在」。少即是贵。
3. **靠字重和留白做层级，不靠容器**。这正是我们要的「文本不要气泡」。

**我们做的是「同方向」，不是「抄 Claude」**：字体栈、栅格、组件结构全部自己定；
配色采用同一套「暖纸 / 陶土」的工作假设（这是你明确要的），但色值按 WCAG 对比度重新校准，
并给出属于自己的语义命名。

### 3.2 色彩 Token（可直接落地）

```css
:root {
  /* ---- 纸面（背景层次，由浅到深） ---- */
  --canvas:      #faf9f5;  /* 主背景：会话区、登录页 */
  --surface:     #f5f4ed;  /* 抬起面：侧栏、输入井、弹窗 */
  --surface-2:   #f0eee6;  /* 悬停 / 内嵌 / 选中 */
  --line:        #e8e6dc;  /* 主分隔线（1px 实线） */
  --line-strong: #d1cfc5;  /* 强调分隔 / 滚动条 */

  /* ---- 墨色（文字，由深到浅） ---- */
  --ink:   #1a1918;  /* 正文、标题 —— 对 canvas 约 16.8:1 */
  --ink-2: #3d3d3a;  /* 次级正文 —— 约 10.4:1 */
  --ink-3: #6e6d67;  /* 元数据、时间戳 —— 4.71:1 on surface（≥12px 可用） */
  --ink-4: #8a8880;  /* 仅用于装饰性分隔，不用于文字 */

  /* ---- 强调（唯一高饱和色） ---- */
  --clay:       #d97757;  /* 主按钮、选中、焦点环 */
  --clay-hover: #c6613f;
  --clay-press: #b25334;
  --clay-btn:   #bd5735;  /* 主按钮底色：白字 4.59:1（--clay 白字仅 3.12，不可用于按钮文字） */
  --clay-soft:  #f8ebe5;  /* 极浅底：仅用于选中态/高亮行 */

  /* ---- 语义色（只表达状态，不做装饰） ---- */
  --ok:     #629987;  /* 矿物绿：成功 / 工具完成 */
  --warn:   #a8763a;  /* 琥珀：压缩、降级 */
  --danger: #bf4d43;  /* 陶土红：错误 / 停止 */

  /* ---- 图表数据系列（数据可视化专用的第三方色，非页面设计色） ---- */
  --series-1: #d97757;  /* 陶土 */
  --series-2: #6a9bcc;  /* 天空蓝 */
  --series-3: #629987;  /* 矿物绿 */
  --series-4: #b0aea5;  /* 暖灰 */
  --series-5: #ebc9b7;  /* 桃色 */
}
```

**对比度实测**（实施时用脚本复核，不得低于此值）：

| 组合 | 比值 | 结论 |
|---|---|---|
| `--ink` on `--canvas` | **16.66:1** | AAA |
| `--ink-2` on `--canvas` | **10.34:1** | AAA |
| `--ink-3` on `--canvas` | **4.93:1** | AA |
| `--ink-3` on `--surface` | **4.71:1** | AA（最严场景，仍达标） |
| `#fff` on `--clay-btn` | **4.59:1** | AA（主按钮默认态） |
| `#fff` on `--clay-press` | **5.02:1** | AA（按下 / 选中文字） |
| `--danger` on `--canvas` | **4.57:1** | AA |
| `--ok` on `--canvas` | 3.10:1 | 仅作图形（状态点），不作文字 |
| `--warn` on `--canvas` | 3.75:1 | 仅作图形，不作文字 |
| `#fff` on `--clay` | 3.12:1 | **不可用于文字**，仅作焦点环/选中底色 |

> ⚠️ 实施注意（实测修正）：`#fff` 压 `#d97757` 只有 **3.12:1**，**主按钮绝不能白字配 `--clay`**。
> 主按钮底色必须用 `--clay-btn: #bd5735`（4.59:1），hover → `--clay-press`（5.02:1）。
> `--clay` 本体只用于焦点环、选中高亮、图形点缀等非文字场景。
> 页面上所有「白字压色」的按钮，实施后都要用脚本复核一遍，这是最容易翻车的地方。

### 3.3 字体

```css
:root {
  --font-sans: -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC",
               "HarmonyOS Sans SC", "Microsoft YaHei", sans-serif;
  --font-serif: "Songti SC", "Noto Serif SC", "Source Han Serif SC",
                "Georgia", serif;
  --font-mono: ui-monospace, SFMono-Regular, "Cascadia Mono", Menlo, Consolas, monospace;
}
```

- **正文/UI 用无衬线**：中文界面用衬线正文在小字号下笔画会糊，Operate 模式必须优先可读性。
- **标题用衬线**（h1 / 空状态大标题 / 登录页 wordmark）：这是唯一的「声音」，
  宋体系在屏幕上比黑体系更有编辑感，且中文用户对「宋体标题」有天然的正式感联想。
- **数字一律 `font-variant-numeric: tabular-nums`**：时间、token 数、工具耗时、图表轴。
- 不引入 Web Font：中文字体子集动辄数 MB，MVP 阶段用系统栈；
  后续若要做品牌化，再考虑自托管 `Noto Sans SC` 的子集（仅常用 3500 字，约 300KB）。

### 3.4 尺度（Scale）

```css
:root {
  /* 间距：4px 基准 */
  --sp-1: 4px;  --sp-2: 8px;  --sp-3: 12px; --sp-4: 16px;
  --sp-5: 24px; --sp-6: 32px; --sp-8: 48px; --sp-10: 64px;

  /* 字号：正文 15px（中文 14px 偏小） */
  --fs-display: 30px;  /* 登录页 wordmark */
  --fs-h1:      22px;  /* 会话标题 / 空状态 */
  --fs-h2:      17px;
  --fs-body:    15px;
  --fs-sm:      13px;
  --fs-meta:    12px;
  --fs-mono:    13px;

  --lh-tight: 1.3;
  --lh-body:  1.72;

  /* 行宽：正文容器最大 68ch / 720px */
  --measure: 720px;

  /* 圆角：只有 4 档 */
  --r-sm: 4px;   /* 标签、小徽章 */
  --r-md: 8px;   /* 按钮、输入框 */
  --r-lg: 12px;  /* 卡片、输入井 */
  --r-xl: 16px;  /* 弹窗 */

  /* 阴影：只有 2 档，且「边框 or 阴影」二选一 */
  --shadow-1: 0 1px 2px rgba(26,25,24,.04), 0 2px 8px rgba(26,25,24,.04);
  --shadow-2: 0 8px 32px rgba(26,25,24,.10);

  /* 缓动 */
  --ease-out: cubic-bezier(.165,.84,.44,1);
  --dur-fast: 120ms;
  --dur-base: 200ms;
}
```

规则：
- **不许出现 6px / 10px / 20px 这类「随手值」**，一律取 token。
- **border 与 shadow 不同时出现在同一元素上**（craft-floor 的 ghost card 禁令）。

## 四、核心改造：消息流去气泡（本次最关键）

### 4.1 新的信息层级模型

把一轮对话看成**三种不同性质**的东西，视觉权重依次递减：

| 层 | 内容 | 形态 | 视觉权重 |
|---|---|---|---|
| **L1 内容** | AI 的回答正文（Markdown） | **直接落在纸面上**，无容器、无边框、无底色 | 100% |
| **L2 过程** | 思考、工具调用、图表、摘要 | 轻量「步骤行」/ 独立内容块，与正文同列但更淡 | 40–60% |
| **L3 元信息** | 时间、模型、token、状态 | 12px 灰字，仅在需要时出现 | 15% |

关键判断：**用户消息是「输入」，AI 回答是「输出」**。
输入需要容器（表明「这是我说的」），输出不需要（它就是这个页面的主体内容）。

> 这跟写作类产品（Notion AI、Claude、ChatGPT 的 canvas 模式）一致：
> 回答越长越像文档，越不该被一个框框住。

### 4.2 消息行结构（改后）

```
┌─ 会话列（max 720px 居中）──────────────────────────┐
│                                                    │
│  [用户消息]                                        │
│  ┌──────────────────────────────────┐             │
│  │ 你这个图看不出区别，换个画法       │  ← 浅暖底   │
│  └──────────────────────────────────┘  右对齐      │
│                                        (surface-2) │
│                                                    │
│  [AI 回答]  ← 无头像、无气泡                       │
│  ┌ 步骤行：chart_spec · 2 次 · 已完成 ────────┐   │
│  └────────────────────────────────────────────┘   │
│                                                    │
│  这是改后的图表，可以看出 3 月和 6 月出现明显      │
│  的拐点……                                          │
│                                                    │
│  （Markdown 正文直排，15px / 1.72 / 720px）        │
│                                                    │
│  ┌ 图表卡片（独立内容块，唯一保留边框的东西）─┐   │
│  └────────────────────────────────────────────┘   │
│                                                    │
└────────────────────────────────────────────────────┘
```

具体规则：

**用户消息**
- 保留「容器感」，但去掉气泡的尖角与高饱和：
  `background: var(--surface-2)`，`border-radius: var(--r-lg)`，**无边框**，右对齐，最大宽度 `min(78%, 560px)`。
- 气泡尾巴（`border-top-right-radius:4px` 那种）**删除** —— 它是 2010 年代聊天软件的语汇，与「纸质文档感」冲突。
- 头像删除（见 4.4）。

**AI 正文**
- **零容器**：`.msg.assistant .bubble` 改为
  `background: transparent; border: none; padding: 0; border-radius: 0;`
- 字号 15px、行高 1.72、最大宽度 `var(--measure)`。
- 文本与步骤行之间用 `--sp-3`(12px) 间距，段间用 `.markdown-body p{margin: 0 0 14px}`。

**步骤行（替代原 tool-card）**
- 单行、无边框、无底色；左侧一个 2px 宽的状态条（`border-left` **禁止**，用伪元素或图标代替，
  见 craft-floor「A colored border-left above 1px on cards is refused」）。
  实际做法：左侧一个 **8px 的圆点**（状态色：运行中=clay 脉冲，完成=ok 实心，失败=danger）。
- 文案：`工具名 · 参数摘要 · 耗时`，13px，`--ink-3`。
- 点击展开才显示完整参数与结果，展开区域用 `--surface` 底 + `--r-md` 圆角 + `--sp-3` 内边距。
- 多个连续工具调用合并为一组，顶部显示 `3 个步骤 · 全部完成`。

**图表**
- 图表是**内容**不是过程，保留卡片形态（这是全站唯一该有边框的块），
  但底色改 `--canvas`（与纸面同色）+ `--line` 细边 + `--r-lg`，去掉阴影。

**摘要（上下文压缩）**
- 降为一枚居中细胶囊：`--surface-2` 底、12px 字、`--ink-3`，仅一条分隔线；
  点击展开看摘要正文。

### 4.3 空状态（首屏）

现在是裸文字「开始对话」。改为：

```
        （衬线大标题，--fs-h1）
        今天想让我做什么？

        （三个可点击的示例胶囊，13px）
        ┌ 算一下 128×37       ┐ ┌ 现在几点 ┐ ┌ 帮我分析一个 CSV ┐
```

- 标题用 `--font-serif`，`--ink`。
- 示例胶囊 `--surface` 底 + hover 抬 1px + `--clay` 文字。
- 点击直接填入输入框并聚焦（不自动发送）。

### 4.4 头像处理

**删除双方头像。**
理由：
1. AI 那边是「文档」，不是「一个人跟我聊天」，头像强化了「聊天软件」的错误心智。
2. 用户侧右对齐 + 底色已经足够区分。
3. 省掉 30px 固定宽度，正文可用宽度更充裕，720px 排版才放得下。

> 如果后续想做「多人格 / 多 Agent」，再按 agent 区分「名字标签」而非头像，
> 标签用 `.agent-tag`（12px、`--surface-2` 底、`--r-sm`）。

## 五、外壳改造：侧栏 / 顶栏 / 输入区

### 5.1 整体布局

保持 `侧栏 264px + 主区` 的结构（Operate 模式：熟悉的导航别乱动），但改视觉：

| 区域 | 现状 | 改后 |
|---|---|---|
| 侧栏底色 | `--panel: #fff` | `--surface: #f5f4ed`（比主区**深**一档，形成「纸垫」关系） |
| 侧栏分隔 | `1px solid #e3e6eb` | `1px solid var(--line)`，并**删掉** `box-shadow` |
| 主区底色 | `#f5f6f8` 冷灰 | `--canvas: #faf9f5` 暖纸 |
| 顶栏 | 白底 + 下边框 | `--canvas` 底 + `--line` 下边框（与内容同底，避免「两条横带」） |
| 内容列 | 820px | `720px`（`--measure`），左右各 20px 安全边 |

> 侧栏比主区**深**，而不是更白 —— 这是 Claude / Linear / Things 的通用做法：
> 让「工作区」成为最亮的地方，注意力自然落在内容上。当前实现是反过来（侧栏纯白、内容灰），
> 导致眼睛一直被左侧吸走。

### 5.2 「新建会话」按钮

现在是通栏蓝色实心按钮，视觉上比任何一条消息都重 —— 又一个权重倒置。

改后：
- 通栏、`--surface-2` 底、`--ink` 文字、`--r-md`、**无阴影**；
- hover → `--canvas` 底 + `--line-strong` 1px 边；
- 左侧一个 `+` 图标（SVG，1.5px stroke）。

理由：新建会话是**低频**操作，不该抢主视觉。强调色留给「发送」这一个真正的主动作。

### 5.3 会话列表项

```
┌─────────────────────────────────────┐
│ 2026年7月全国宽带用户数分析          │ ← 13px --ink
│ 刚刚 · 12 条消息                     │ ← 11px --ink-3 tabular
└─────────────────────────────────────┘
```

- 去掉 `border`（选中态用 `--surface-2` 底 + `--clay` 左侧 2px 指示条 …… 不，禁止 border-left，
  改为**整个背景 `--clay-soft` + 文字 `--ink`**）。
- 行高 `--sp-5`(24px) padding，`--r-md`。
- 删除按钮在 hover 时以 24×24 图标按钮淡入。

### 5.4 输入区（Composer）

这是全站**唯一**需要「浮起感」的地方（它是用户的注意力焦点）。

```
     ┌──────────────────────────────────────────────┐
     │  输入消息…                              [↑]  │  ← 井：--canvas 底
     └──────────────────────────────────────────────┘     --line-strong 边
        Enter 发送 · Shift+Enter 换行 · /compact 压缩      --shadow-1
```

- 整条输入区不再是「顶边 + 白底」的横带，改为**悬浮井**：
  `max-width: var(--measure)`，`--r-xl`(16px)，`1px solid var(--line-strong)`，`--shadow-1`。
- 输入框本身 `background: transparent; border: none;`，把边框让给外层井。
- 发送按钮改为 **36×36 圆形图标按钮**（`↑` 箭头 SVG），底色 `--clay-btn`，白字；
  空输入时降为 `--line-strong` 底 + `--ink-4` 字（disabled 但是「灰」不是「半透明」）。
- **删掉 `composer-hint` 那行「自研 Agent 内核 · 工具由 FastMCP 提供 · 会话持久化于 SQLite」**：
  这是给开发者看的，不是给用户看的，且占掉了页面底部一条视觉带。
  （如果一定要保留，挪到设置里的「关于」。）
- 顶部再加一行 12px 的 `--ink-3` 提示，仅在首次使用/空会话时出现。

现状：居中一个 380px 白卡片 + 蓝色圆角 logo，标准 SaaS 模板。

改后（**仍然保持极简单栏**，Operate 产品不需要营销页）：

│              └────────────────────────────┘          │

│              ┌────────────────────────────┐          │
│              └────────────────────────────┘          │
│              ┌────────────────────────────┐          │
│              │          登 录             │          │ ← clay-hover 实心
│              └────────────────────────────┘          │
│                                                      │
│              切换到注册 →                             │  ← 文字按钮
│                                                      │

关键变化：
- **删掉卡片容器**（`background:#fff; border-radius:16px; box-shadow`）—— 直接落在纸上。
  表单宽度 320px，居中。
- **删掉 logo 方块**。文字 wordmark 用衬线体即可（craft-floor 反对「圆角方块 + 两字母」这种占位式 logo）。
- 输入框：`--canvas` 底 + `1px --line-strong`，focus 时 `--clay` 边框 + `2px --clay-soft` 外环。

  少一个控件、少一层视觉噪音。
- 错误提示：`--danger` 文字 + `--clay-soft` 底（不用红色块）。

### 6.2 设置弹窗

- 遮罩：`rgba(26,25,24,.32)` + `backdrop-filter: blur(2px)`（这是**功能性**模糊，不是装饰）。
- 弹窗本体：`--canvas` 底、`--r-xl`、`--shadow-2`、**无边框**（阴影与边框二选一）。
- Tab：从「下划线 tab」改为**左侧垂直列表**（Operate 模式里，设置项多时竖排更好扫），
  宽 180px，选中项 `--surface-2` 底 + `--ink` 字。
- 表单控件统一 `--canvas` 底 + `--line-strong` 边 + `--r-md`、13px。
- 「保存」按钮用 `--clay-btn`，其余操作按钮用 ghost 样式（`--canvas` 底 + `--line` 边）。
- MCP JSON 文本框：`--surface` 底、`--font-mono` 13px、`--r-md`、行高 1.6。

## 七、图标系统（替换 emoji）

当前用 `🔧` `🗜️` `+` `×` 等字符。craft-floor 明确禁止 emoji 当图标。

方案：**内联 SVG，统一 1.5px stroke、`stroke-linecap:round`、24×24 viewBox**。
不引入图标库依赖（Operate 产品图标就那么几个），直接在 `frontend/src/components/icons.tsx` 里手写：

| 用途 | 图标 | 尺寸 |
|---|---|---|
| 新建会话 | `plus` | 16px |
| 删除 | `trash` | 14px |
| 工具步骤 | `chevron-right`（展开时 `chevron-down`） | 14px |
| 思考 | `sparkle`（4 尖星） | 14px |
| 压缩 | `archive` | 14px |
| 发送 | `arrow-up` | 16px |
| 停止 | `square`（实心小方块） | 14px |

| 设置 | `sliders` | 15px |

状态点（工具运行/完成/失败）用 `<span class="status-dot">` + CSS 实现，不用图形。
颜色一律 `currentColor`，由父级文字色控制（保证继承语义色）。

## 八、动效与微交互（克制，只有一个签名动作）

Operate 模式的原则：动效只在**反馈**时出现，不做入场动画、不做滚动动画。

### 8.1 全局

```css
* { transition: none; }  /* 不做全局 transition */
button, a, .session-item, .step-row {
  transition: background-color var(--dur-fast) var(--ease-out),
              border-color var(--dur-fast) var(--ease-out),
              transform var(--dur-fast) var(--ease-out),
              color var(--dur-fast) var(--ease-out);
}
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    transition-duration: .01ms !important;
    animation-duration: .01ms !important;
    animation-iteration-count: 1 !important;
  }
}
```

### 8.2 交互反馈清单

| 元素 | hover | active/press |
|---|---|---|
| 主按钮 | 底色 `--clay-btn` → `--clay-press` | `transform: translateY(1px)` |
| Ghost 按钮 | 底色 → `--surface-2`，边框 → `--line-strong` | `translateY(1px)` |
| 会话列表项 | 底色 → `--surface-2` | — |
| 示例胶囊 | `translateY(-1px)` + 边框转 `--clay` | `translateY(0)` |
| 步骤行 | 底色 → `--surface`，展开箭头转动 90° | — |
| 输入井 | 边框 → `--line-strong`（始终）focus 时 → `--clay` + 3px `--clay-soft` 环 | — |

### 8.3 签名动作：状态点的「呼吸」

全站唯一的**持续动画**：工具运行中的状态点做 1.6s 的柔和脉冲（`transform: scale` + `opacity`，
不是 box-shadow 光晕 —— craft-floor 禁止零偏移彩色光晕）。

```css
@keyframes breathe {
  0%, 100% { transform: scale(1);   opacity: 1; }
  50%      { transform: scale(1.35); opacity: .55; }
}
.status-dot.running { animation: breathe 1.6s var(--ease-out) infinite; }
```

它有意义：告诉用户「这个步骤正在跑」。仅此一个，不再加别的循环动画。
流式输出时的光标闪烁保留（`▊`），但改为 `--clay` 色、1s 淡入淡出（不用 steps 硬闪）。

## 九、浏览器原生面（最容易被忽略、性价比最高）

craft-floor 原话：「这些是浏览器默认值，不属于任何设计系统。把它们从调色板里主题化，
是最便宜的『这是被设计过的』信号，也是最常被模型跳过的。」

必须处理：

```css
::selection { background: var(--clay-press); color: #fff; }  /* clay 白字仅 3.12，选中文字用 press */
:focus-visible {
  outline: 2px solid var(--clay);
  outline-offset: 2px;
  border-radius: inherit;
}
/* 统一滚动条（WebKit + Firefox） */
* { scrollbar-width: thin; scrollbar-color: var(--line-strong) transparent; }
::-webkit-scrollbar { width: 10px; height: 10px; }
::-webkit-scrollbar-track { background: transparent; }
::-webkit-scrollbar-thumb {
  background: var(--line-strong);
  border-radius: 999px;
  border: 3px solid transparent;
  background-clip: content-box;
}
::-webkit-scrollbar-thumb:hover { background-color: var(--ink-4); background-clip: content-box; }
/* caret */
textarea, input { caret-color: var(--clay); }
/* 数字 */
.tabular { font-variant-numeric: tabular-nums; }
```

另外：
- `text-wrap: pretty` 加在正文段落（改善中文换行断句）。
- `<html>` 上加 `color-scheme: light`（现已有，保留）。
- 建议同时**移除** `body{-webkit-font-smoothing}` 之外的任何全局 reset 冲突。

## 十、响应式

| 断点 | 变化 |
|---|---|
| ≥1100px | 侧栏 264px + 内容 720px 居中 |
| 768–1100px | 侧栏 220px；内容列改 `min(100%, 720px)` + 左右 24px |
| <768px | **侧栏改为抽屉**（顶部汉堡菜单唤出）；内容满宽、左右 16px；输入井贴底 |
| <480px | 字号降一档（body 14px）；步骤行只显示图标 + 工具名，参数折叠 |

三条硬规则（来自 `design-taste-frontend` 的 390 检查线）：
1. 任何宽度下都不能出现横向滚动。
2. 按钮在 <480px 时撑满宽度。
3. 长代码块 / 长表格内部滚动，不能撑破页面。

## 十三、风险与未决项

| 风险 | 说明 | 应对 |
|---|---|---|
| 去气泡后「谁说的」变模糊 | 少部分用户可能一时不习惯 | 用户消息保留底色 + 右对齐；AI 侧不加任何容器，这是刻意选择 |
| 删除头像影响多 Agent 扩展 | 未来可能有多个 subagent 同时发言 | 用 `.agent-tag` 名字标签替代，见 4.4 注 |
| 衬线标题在 Windows 上回退难看 | `Songti SC` 是 macOS 字体，Windows 会回退 `SimSun`（宋体），小字号发虚 | 只在 ≥17px 使用，并在 Windows 上用 `Microsoft YaHei` 兜底；这是已知取舍，批次 6 换成自托管字体后彻底解决 |
| 暖纸底在低色域显示器上偏黄 | 部分老显示器色偏 | `#faf9f5` 的黄度很浅（ΔE < 2），实测可接受 |
| 实施跨度大 | 5 个批次、约 3 天 | 每批独立可回滚，批次 1 无结构改动风险最低，建议先上 |

**未决**：
- 是否保留「压缩上下文」这个暴露给用户的按钮？（Operate 产品里它更像内部机制；建议收进设置）
- 模型选择器是否收进顶栏右侧的图标按钮（当前横排在标题旁，占空间且视觉噪）
- 是否要做浅色/深色双主题（建议批次 6 再做）

## 十四、附：一句话结论

**当前问题的本质不是「配色不好看」，而是「所有东西长得一样」。**
只要把「内容 / 过程 / 元信息」三层在视觉上拉开，再换上一套有温度的纸面配色，
即使不做任何花哨效果，这个产品也会立刻从「demo」变成「像个正经工具」。
这也是两套 skill 共同的判断：Operate 类产品的高级感来自**克制、层级、和对细节的在意**，
而不是装饰。
