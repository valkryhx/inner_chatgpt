## 1. 启动参数（`launch.py`）

| 环境变量 | 值 | 为什么 |
|---|---|---|
| `HLZ_TURNJOB_HEARTBEAT_IDLE_S` | `4` | 生产默认 15s，静默窗口不够长。压到 4s 让心跳在真机（含 `code_run` 长空档）确定性地出现多次 |
| `HLZ_TURNJOB_REPLAY_FRAMES` | `60` | 生产默认 2000 帧，正常一轮挤不爆，「缓冲溢出 → 降级 sync」永远验不到 |
| `INNER_A2A_ENABLED` | `true` | A2A 必须仍能直接吃 `_event_stream`（本轮给它加了可选 `job` 参数） |
| `INNER_A2A_PUBLIC_BASE_URL` | 本机 | 卡片 URL |
| `HLZ_LOG_LEVEL` / `HLZ_PRELUDE_LOG` | `info` / `1` | 从日志读事务与首帧计时 |

**刻意保持生产默认**（改了等于没验）：

- `INNER_A2A_SYNC_TIMEOUT_S` 不设，保持 60s —— A2A 长任务语义要按生产值验；
- `HLZ_MEMORY_SELECTOR` / `HLZ_MEMORY_AUTO_WRITE` 不设 —— 记忆与本轮无关，
  开着只会多出模型调用、拖慢每一轮、污染「一轮跑多久」的观测。

## 4. 三个「假失败」与一个真缺陷

### 4.1 假失败①：「写 N 字长文」不可靠

V-2/V-5/V-8 第一版用「写一篇 8000/15000 字长文」。实测该 prompt **有时 743ms
就收尾**（首帧即末帧），于是断开时那一轮早 `complete` 了，续看只收到一帧 `done`。

### 4.2 假失败②：编号列表产帧多但**只跑 1~2 秒**

换成「输出 1..600 编号列表」后，实测：

```
第0次：总时长=1.9s  frames=603  status=complete
第1次：总时长=1.2s  frames=603
第2次：总时长=1.0s  frames=603
第3次：总时长=1.0s  frames=603
第4次：总时长=1.0s  frames=603
```

帧数够（603），但**总时长只有 1~2 秒**，断开时仍是 `complete`。

**这里我犯了一次和阶段 4 同类的错**：先前用 `_probe_framecount.py` 测到「20 秒内
1024 帧」，就以为「20 秒还没跑完」。实际上那个探针是**自己主动停在 20 秒**，
不是模型还在跑 —— 又一次「探针伪造现象」。

最终正解：用 `code_run` 里的 `sleep` 让 job 真的一直活着（`SLOW_PROMPT`），
并给 `disconnect_and_resume()` 加了「断开后查库，若不是 streaming 就重开会话重试」。

### 4.3 假失败③：V-5b 第一版是空过

第一版写成：

```python
contiguous = (not later) or (later[0] == sync_seq + 1)
```

「根本没收到后续帧」时 `not later` 为真 → **无条件通过**。实测第一次跑报 `OK`
但详情是「之后首个=无」——没有帧还判过，是典型的空断言。

改成必须 `bool(later) and later[0] == sync_seq + 1`，并把「没收到」明确记为失败。
改完第一次就诚实报 FAIL（当时窗口 12 秒只等到心跳注释帧），把窗口改成「等到至少
2 个事件帧」后才是真成立。

### 4.4 真缺陷：启动器没隔离数据库

第一版 `launch.py` 直接打 `backend/data/app.db`。一次自测留下
**16 个账号 / 91 会话 / 176 消息**，A2A 回归又添 15 个账号。

虽然事先按铁律备份了（`work/db_backup/app_20261115_095933.db`，已验 0 个 `@t.local`），
但**备份不等于没污染** —— 还得逐条清理并验证干净。

修法：启动器默认把 DB 复制到 `work/turnjob_verify/app.db`（`sqlite3.backup`，WAL 安全），
逐模块改 `DB_PATH`（`config` / `db` / `history_store` / `memory_store` / `team_store` /
`subagent.store` / `a2a.store` / `turn_marker` 各有自己的常量 —— **不存在
`HLZ_DB_PATH` 这个环境变量**）。要打生产库必须显式 `--use-prod-db`。

### 4.5 污染已完整回滚

按 RUN_ID 时间戳圈定本轮（`>= 1794708072`）的 31 个账号，级联删除后与备份逐表比对：

—— 隔离机制确实生效。
