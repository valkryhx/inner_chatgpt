# Hlaudz 任意格式文件下载设计方案（2026-11-06）

> 一句话摘要：在现有「workspace 图片鉴权读取」基础上，新增通用文件下载端点（任意 MIME、中文文件名、Range 大文件）与三类前端入口（Markdown 链接、工具步骤、工作区面板），让 `.docx/.xlsx/.pptx/.pdf/.zip/.csv/.py/.md` 等产物都能一键下载；全程保持用户隔离与现有契约不变。
> 日期：2026-11-06 · 状态：已实施（P1–P3 完成，P4 产物登记未做；实施记录见 `docs/20261106-任意格式文件下载实施记录.md`）· 关联：`docs/20261105-Markdown图片渲染修复.md`、`docs/20261105-Skill与基础工具设计与实施.md`

---

## 1. 背景与现状

### 1.1 现在能下载什么

| 类型 | 现状 | 实现位置 |
|---|---|---|
| 图片（png/jpg/gif/webp/svg…） | ✅ Markdown 里渲染，可右键另存 | `GET /api/me/workspace-image` + `MarkdownImage`（fetch + Bearer → blob） |
| 图表 | ✅ 「下载 PNG」按钮（客户端 ECharts 导出） | `ChartView.tsx` |
| 其它任意文件 | ❌ 无入口：Markdown 里的 `[报告](reports/q3.docx)` 点开是 SPA 404；`<a>` 也无法带 `Authorization` | — |

### 1.2 产物落在哪里

- 用户沙箱：`backend/data/workspaces/<user_id>/`（`config.WORKSPACES_DIR`）；
- 根代理写文件：workspace 根（`file_write` / `file_patch` / `code_run`）；
- 子代理写文件：`workspaces/<user_id>/.subagents/<session_id>/<agent>/`（写根隔离）；
- 所有路径都经过 `workspace.safe_workspace_path / safe_read_path`，`resolve()` 后校验包含关系，越界直接 `PathSecurityError`。

### 1.3 相关约束（来自 AGENTS.md）

1. SSE/HTTP/前端契约不得破坏 → 新能力用**新增**端点与**可加**字段；
2. 多用户隔离 → 任何下载都必须按 `user_id` 解析，不接受前端传入的根目录；
3. 不引入新框架/库 → 后端只用 FastAPI/Starlette 自带 `FileResponse`（已支持 `Range`/206，实测 starlette 1.10.0）；
4. 文件一律 UTF-8/LF，临时产物放 `work/`。

## 2. 目标与非目标

### 2.1 目标

1. **任意格式**可从 UI 下载：文本、源码、CSV、ZIP、PDF、Office（docx/xlsx/pptx）、二进制；
2. 三个入口：**对话里的 Markdown 链接**、**工具步骤行**、**工作区文件面板**；
3. 下载语义正确：`attachment`、中文文件名（RFC 5987）、大文件流式、断点续传（206）；
4. 安全：只读当前用户 workspace；防穿越/软链；HTML/SVG 不内联执行；大小与数量限额；
5. 不改变现有图片接口与 SSE 契约。

### 2.2 非目标（v1 不做）

- 在线预览/编辑 Office、PDF 渲染（v2 可用白名单 `inline=1`）；
- 公开分享链接、跨用户共享（未来可做签名 URL）；
- 把整个 workspace 一键打包（避免无意带出全部子代理产物）；
- Excel/Word 的**生成**能力（下载与格式无关；生成依赖运行环境是否装了 `openpyxl/python-docx/python-pptx`，见 §9）。

## 3. 方案对比与决策

| 方案 | 结论 | 原因 |
|---|---|---|
| A. 静态挂载 `workspaces/` 目录 | ❌ | 无鉴权；目录遍历；MIME 嗅探可能执行 HTML/SVG；多用户直接互读 |
| B. 扩展现有 `workspace-image` 接受任意类型 | ❌ | 图片接口语义被污染；inline 白名单难收紧；旧前端行为漂移 |
| C. 新增独立下载端点 + 前端统一下载组件 | ✅ 采纳 | 契约清晰、安全边界好写、可灰度 |
| D. 签名 URL（`?sig=&exp=`，可给 `<a href>` 直下） | ⏳ 未来 | 能省掉 blob 中转，但要引入签名密钥与过期策略；v1 用 Bearer + blob 足够 |

**决策**：新增 `/api/me/workspace-file`（单文件）与 `/api/me/workspace-files`（列表）、`/api/me/workspace-zip`（打包）三个端点；前端新增 `downloadWorkspaceFile()` 与 `FileChip` / `WorkspacePanel`；图片接口保持原样。

## 4. 后端设计

### 4.1 路径解析（复用现有安全逻辑）

把 `routers/media.py::normalize_workspace_media_path` 抽到 `workspace.py`，命名 `normalize_workspace_path(raw)`（media.py 保留同名薄包装，避免前端/测试引用变化），统一支持：

- 相对路径 `reports/q3.docx`、`./a.csv`；
- Windows 绝对路径 `D:/x/a.docx`、`D:\x\a.docx`；
- `file:///D:/x/a.docx`（先 `urlparse` + `unquote`）；
- 沙箱别名 `/workspace/x`、`workspace/x`、`/x`。

下载**只允许 workspace 根**（`user_workspace(user_id)`），不开放 skills 目录（如未来要开放，单独加 `scope=skills` 开关）。

```python
# backend/app/workspace.py（新增）
def resolve_workspace_download(user_id: str, raw: str) -> Path:
    p = normalize_workspace_path(raw)                 # 统一分隔符/别名/解码
    base = user_workspace(user_id)                    # 已含 _reject_unsafe_segment
    target = (base / p) if not Path(p).is_absolute() else Path(p)
    target = _resolve_under(base, target)             # resolve 后校验包含关系（防软链逃逸）
    if not target.is_file():
        raise FileNotFoundError(target)
    return target
```

### 4.2 API 契约（新增，均为 `GET/POST /api/me/...`）

#### ① 单文件下载

```http
GET /api/me/workspace-file?path=reports/q3.docx
Authorization: Bearer <token>
```

- 200：`FileResponse`
  - `Content-Type`：扩展名表优先，其次 `mimetypes.guess_type`，未知 → `application/octet-stream`；
  - `Content-Disposition: attachment; filename="q3.docx"; filename*=UTF-8''%E6%8A%A5%E5%91%8A.docx`（Starlette `FileResponse(filename=...)` 自动生成 RFC 5987 头）；
  - `X-Content-Type-Options: nosniff`、`Cache-Control: private, max-age=0, must-revalidate`；
  - `Accept-Ranges: bytes`，`Range` 请求返回 206（Starlette 1.10 内置）。
- 400 空路径 / 403 越界（含软链） / 404 不存在或不是文件 / 413 超过 `MAX_DOWNLOAD_BYTES`（默认 200MB）。
- 可选 `inline=1`：仅白名单（`text/plain`、`text/markdown`、`application/json`、`application/pdf`、图片）返回 `Content-Disposition: inline`，其余 415；**默认永远 attachment**。

MIME 补全表（`mimetypes` 在 Windows 上对 Office 类型不可靠）：

```python
EXTRA_MIME = {
    ".docx": "application/vnd.openxmlformats-officedocument.wordprocessingml.document",
    ".xlsx": "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet",
    ".pptx": "application/vnd.openxmlformats-officedocument.presentationml.presentation",
    ".doc": "application/msword", ".xls": "application/vnd.ms-excel",
    ".ppt": "application/vnd.ms-powerpoint",
    ".odt": "application/vnd.oasis.opendocument.text",
    ".ods": "application/vnd.oasis.opendocument.spreadsheet",
    ".odp": "application/vnd.oasis.opendocument.presentation",
    ".7z": "application/x-7z-compressed", ".rar": "application/vnd.rar",
    ".md": "text/markdown; charset=utf-8",
}
```

#### ② 目录列表（给「工作区文件」面板）

```http
GET /api/me/workspace-files?path=&depth=2&limit=500
```

```json
{
  "root": "",
  "entries": [
    {"name": "reports", "path": "reports", "type": "dir", "size": 0, "mtime": 1793968000},
    {"name": "q3.docx", "path": "reports/q3.docx", "type": "file",
     "size": 38211, "mtime": 1793968120, "hidden": false}
  ],
  "truncated": false
}
```

规则：目录优先 + 名称排序；跳过隐藏系统项（`.git` 等）；`.subagents/` 默认返回但标 `hidden: true`，前端折叠为「子代理产物」；`limit` 上限 1000；不跟随软链。

#### ③ 打包下载

```http
POST /api/me/workspace-zip
{"paths": ["reports/q1.docx", "reports/q2.xlsx", "data/export.csv"]}
→ 200 application/zip（附件 report-20261106.zip）
```

- 上限：`MAX_ZIP_FILES=100`、`MAX_ZIP_BYTES=500MB`（先统计总大小，超限 413）；
- 用 `tempfile.SpooledTemporaryFile` + `zipfile.ZipFile` 写临时包，`BackgroundTask` 删除；
- 条目名用规范化后的相对路径，**去重并剥离 `..`**（防 zip slip）；只收文件，忽略目录；
- 任一 `path` 非法/不存在：整体 400/404，不生成半包（先校验后打包）。

#### ④ 配置（`config.py` / 环境变量）

```text
MAX_DOWNLOAD_BYTES = 200MB
MAX_ZIP_FILES      = 100
MAX_ZIP_BYTES      = 500MB
DOWNLOAD_DENY_EXT  = ""        # 企业可配 exe,bat,cmd,dll（默认不拦，一律 attachment）
```

### 4.3 产物登记（P4，可选但推荐）

给「本轮生成了哪些文件」提供可靠数据源，避免前端靠解析模型输出：

```sql
CREATE TABLE IF NOT EXISTS workspace_artifacts (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL,
  session_id TEXT NOT NULL,
  generation_id TEXT,
  message_id TEXT,
  path TEXT NOT NULL,          -- workspace 相对路径（POSIX）
  size INTEGER NOT NULL,
  sha256 TEXT,
  created_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_wa_session ON workspace_artifacts(user_id, session_id, created_at);
```

- 写入点：`file_write` / `file_patch` 成功后登记；`code_run` 复用 `run_guard` 已有的 Python 写审计钩子登记；
- SSE/消息块新增（**加法，不破坏旧前端**）：tool_result 后追加 `{"type": "file", "path": "...", "name": "...", "size": 123}`；
- 前端按块渲染「本轮生成 2 个文件」条，直接复用 FileChip。

## 5. 前端设计

### 5.1 统一下载函数（`frontend/src/api.ts` 或 `utils/download.ts`）

```ts
export async function downloadWorkspaceFile(path: string, fallbackName?: string) {
  const token = getToken()
  const res = await fetch('/api/me/workspace-file?path=' + encodeURIComponent(path), {
    headers: token ? { authorization: 'Bearer ' + token } : undefined,
  })
  if (!res.ok) throw new Error(await readableError(res))   // 403/404/413 给中文提示
  const disp = res.headers.get('content-disposition') || ''
  const name = filenameFromDisposition(disp) || fallbackName || path.split('/').pop() || 'download'
  const url = URL.createObjectURL(await res.blob())
  const a = document.createElement('a')
  a.href = url; a.download = name; a.click()
  setTimeout(() => URL.revokeObjectURL(url), 30_000)
}
```

`filenameFromDisposition` 优先解析 `filename*=UTF-8''...`，其次 `filename="..."`，解码 `decodeURIComponent`。

### 5.2 Markdown 链接 → 文件卡片

- 复用 `MarkdownImage.isWorkspaceImage` 的判定逻辑（抽成 `isWorkspaceLocal(src)`）；
- `Markdown` 的 `a` 组件：若是**本地 workspace 路径且非图片扩展名** → 渲染 `<FileChip path name/>`，点击下载（`preventDefault`），不再 `target=_blank`；
- 判断图片扩展名：`.png/.jpg/.jpeg/.gif/.webp/.bmp/.avif/.svg`；
- 远程链接保持现有 `<a>` 行为；
- `[下载](q3.docx)`、`[下载](/workspace/q3.docx)`、`[下载](D:/.../q3.docx)` 都命中。

### 5.3 工具步骤行下载

- `StepRow`：当 `block.name` 为 `file_write`/`file_patch` 且 `input.path` 是字符串 → 行尾加「下载」小按钮（不再依赖结果文本里的绝对路径）；
- `code_run`：行尾加「工作区」按钮，打开文件面板（因为输出文件不可枚举）；
- 下载按钮需 `stopPropagation`，不能触发展开/收起。

### 5.4 工作区文件面板（`WorkspacePanel.tsx`）

- 入口：主区顶栏「文件」按钮（与模型选择器同排）；打开右侧抽屉（复用 TeamPanel 的宽度/动效 token）；
- 内容：面包屑 + 列表（图标、名称、大小、修改时间）；点击文件直接下载；目录点击进入；
- 多选 → 「打包下载」（`POST /workspace-zip`）；
- 顶部「刷新」；空态：「本轮生成的文件会出现在这里」；
- 移动端（≤720px）全屏抽屉，列表行高 ≥44px；
- 记住当前目录（`localStorage`，按 user_id 隔离，复用 BUG-14 的做法）。

### 5.5 样式与可访问性

- 复用暖纸/陶土 token；`FileChip` 为小胶囊（图标 + 名称 + 下载箭头），失败时红字提示；
- 图标按扩展名映射：📄 文本 / `{ }` 代码 / `▦` 表格 / `◫` 演示 / `⛁` 数据 / `◈` 压缩包（用 CSS 画或内联 SVG，不引资源）；
- 下载中显示「准备中…」，完成后恢复；aria-label 含文件名。

## 6. 安全设计（逐条对应现有边界）

1. **身份**：端点统一 `Depends(get_current_user)`，路径只相对当前用户 workspace 解析，前端传不了根；
2. **穿越/软链**：`normalize` + `Path.resolve()` + `_resolve_under`；含 `..`、绝对路径越界、指向 workspace 外的软链全部 403；
3. **MIME 嗅探**：`X-Content-Type-Options: nosniff`；非白名单一律 `attachment`；HTML/SVG 不可能以 `text/html` inline 打开（SVG 仅图片端点，且带 CSP sandbox）；
4. **文件名注入**：`Content-Disposition` 用 Starlette 的 RFC 5987 生成；自造头时剥离 `"`、`\r`、`\n`；
5. **zip slip**：条目名只取归一化后的相对路径，去 `..`、去前导 `/`，重名自动追加序号；
6. **资源**：单文件 200MB、zip 100 个/500MB、列表 1000 项；`FileResponse` 流式发送，Range 支持断点续传；
7. **不泄露**：不提供目录打包全部 workspace；`.subagents` 明确标注来源；DB/密钥不在 workspace 内，天然不可达。

## 9. 风险与未决项

1. **Office 生成**：下载与格式无关，但模型要真的产出 `.docx/.xlsx/.pptx`，运行环境需 `python-docx/openpyxl/python-pptx`（当前 requirements 未包含）。可选方案：加入依赖、或让模型用标准库 `zipfile` 手写 OOXML（复杂），或在 Skill 里内置生成脚本。建议 P4 前单独决策。
2. **大文件与反代**：Nginx 默认缓冲会占内存，部署侧建议 `proxy_buffering off` 或调大 `proxy_max_temp_file_size`；`FileResponse` 已支持 Range，无需自写 206。
3. **Windows 文件名**：保留名（CON/PRN）、非法字符（`:*?"<>|`）由 `file_write` 侧提示，下载端只做只读服务；超长路径依赖长路径支持。
4. **inline 预览**：v1 只做下载。若后续要 PDF 内联，需给响应加 `Content-Security-Policy: sandbox` 并在前端用 `<iframe>` 同源 blob。
5. **下载审计**：v1 不记录；多租户合规场景可把下载事件写入 `workspace_artifacts` 或独立审计表。
6. **签名 URL**：如果未来要支持「复制链接给别人下载」，需要 `HMAC(path+exp)` 签名端点与短期过期，属于独立设计。
7. **token 过期**：blob 下载 401 时前端提示「登录已过期」，不自动重试，避免半截文件。
