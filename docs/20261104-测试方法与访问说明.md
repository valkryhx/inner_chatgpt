> 项目：LangGraph/LangChain Web Agent MVP（多用户 + 会话隔离 + 用户级 APIKey/MCP）
> 适用：交付后用户自测 / 联调验收
> 更新：2026-11-04

## 1. 访问方式

### 1.1 一体化访问（推荐，前端已由后端托管）

浏览器直接打开：

```
http://127.0.0.1:8000/
```

- 后端在后台运行，监听 `127.0.0.1:8000`；前端为已构建产物 `frontend/dist`，由 FastAPI 在 `/` 单端口托管。
- 首次访问会看到**登录/注册页**：先「注册」一个账号（邮箱 + 密码≥4 位），注册成功即自动登录。
- 健康检查（无需登录）：

```
GET http://127.0.0.1:8000/api/health
```

预期返回：

```json
{"ok":true,"model":"deepseek-v4.1-flash","mcp_tools":0}
```

> 说明：`mcp_tools` 是全局默认工具数；登录后每个用户的实际工具数以「设置 → 我的 MCP」里的“当前生效工具”为准（默认 5 个内置工具）。

### 1.2 前端开发模式（需热更新时）

1. 后端保持运行（占用 8000 端口）。
2. 另开终端：

```bash
cd frontend
npm run dev
```

3. 浏览器打开 `http://127.0.0.1:5173/`（Vite 已把 `/api` 代理到 8000）。

### 1.3 启动 / 停止

- 启动后端：

```bash
cd backend
python run.py
```

- 查看 8000 端口占用（Git Bash）：

```bash
netstat -ano | grep :8000
```

- 停止后端（用上一步查到的 PID）：

```bash
taskkill //PID <PID> //F
```

> 若机器重启或端口被占用，需重新 `cd backend && python run.py`。

## 2. 功能自测清单（建议路径）

### 2.1 基础 Agent 能力（登录后）

1. **新建会话**：点左上「+ 新建会话」，侧栏出现新条目。
2. **流式对话 + 工具调用**：输入「现在几点？顺便算 128*37」并回车。
   - **思考内容**：对较长/需要推理的问题，assistant 气泡上方会出现「思考过程（点击收起）」折叠区，**默认展开**展示模型推理文本；可点击折叠。短问答模型可能不产生思考，属正常。
   - 出现两个工具卡片：`current_time`、`calculator`（含参数与结果）。
   - 正文逐字流式输出，含当前时间与 `128 × 37 = 4736`。
3. **持久化 / resume**：刷新页面，历史仍在（SQLite）。
4. **上下文连续**：追问「再减 1」，应基于上一轮结果连续作答。
5. **停止生成**：发长回复请求后点「停止」，已产出内容保留、状态为已停止。
6. **删除会话**：侧栏会话项悬停出现「×」，确认后从列表消失。
7. **上下文压缩**：两种方式等价——
   - 顶栏点「压缩上下文」按钮；
   - 或输入框输入 `/compact`（可加自定义要求，如 `/compact 重点保留数字`）后发送。
   - 生效表现：历史中出现一张「🗜️ 上下文已压缩」摘要卡片（显示触发方式/摘要 tokens/保留与压缩条数，可展开看摘要正文），侧栏会话显示「已压缩」；刷新后摘要卡仍在。
8. **重命名**：侧栏双击会话标题可改名。

### 2.1.1 会话级模型切换（新增）

- 顶栏「模型」下拉：列出你在「设置 → 我的 APIKey」里配置的所有可用模型（有 key/model/base_url），外加「跟随我的默认」。
- 选择后**仅对当前会话生效**，并持久化到会话（`sessions.model_id`）；切换会话会各自保留其模型。
- 每条回复的实际模型以服务端 `done` 事件为准（区分大小写敏感场景，可用它核对）。
- 同一个会话可在不同轮次切换模型；历史上下文共用（同一 thread）。

### 2.2 多用户 / 隔离能力（重点）

1. **注册登录**：浏览器打开首页出现登录页；注册新账号后进入工作台，侧栏底部显示当前用户与「设置 / 登出」。
2. **用户数据隔离**：用户 A 建若干会话后登出；用户 B 登录后，侧栏看不到 A 的任何会话（后端亦对越权访问返回 404）。
3. **用户级 APIKey**：点「设置 → 我的 APIKey」，新增一条配置（填 Base URL、API Key、模型名等），保存后列表显示 `key sk-****1234` 这类打码值；只有本人可见。
4. **用户级 MCP（标准 mcp.json）**：点「设置 → 我的 MCP」，在编辑框**直接粘贴标准 `mcp.json`（`mcpServers` 格式）**后点「保存（按 name 合并）」。
   - 支持 `stdio`（`command`/`args`/`env`）与 `http`/`sse`（`url`/`headers`）两类；`type` 可省略（有 command 视为 stdio，否则 http）。
   - **按 name 增量合并**：同名覆盖、新名新增，**不会清空**已有其它 MCP 配置（可多次追加）。
   - 配置**持久化**在 SQLite（`user_mcp_servers`），刷新/重启后仍在；已配置项可启用/停用/删除。
   - 顶部“当前生效工具”随配置变化（多服务器工具聚合）。
5. **回退默认**：某用户不配置 APIKey 时，使用系统默认模型（`llm.yaml` 的 default）仍可正常对话。

### 2.3 逐项验收标准

| 用例 | 通过标准 |
|---|---|
| 注册/登录 | 成功后进入工作台，侧栏显示当前用户 |
| 会话隔离 | B 看不到 A 的会话；跨用户读/删返回 404 |
| APIKey 隔离 | 每个用户只看到自己的配置，key 显示为打码值 |
| MCP 隔离 | 每个用户只看到自己的 MCP；生效工具按用户解析 |
| 流式+工具 | 工具卡片出现，正文逐字增长，结果正确 |
| 刷新持久化 | 刷新后消息数量与内容不变 |
| 上下文连续 | 追问能引用上一轮结果 |
| 手动压缩 | 返回 compacted=true，出现压缩标识 |
| 登出 | 回到登录页，清空本地 token 与会话状态 |

## 4. 补充说明

### 4.1 上下文压缩的三级机制

压缩分三级（软线 < 硬线）：

1. **手动 `/compact`**（或顶栏按钮）：用 LLM 把较早消息摘要，保留最近 6 条；写入一张可见摘要卡。
2. **自动软线压缩**：每轮发送前按「已存上下文 token + 本轮输入」判断，超过「软线阈值」时用 LLM
   摘要较早消息并替换为「摘要 + 最近若干条」（至少保留最近 2 条）；前端收到 `compaction(trigger=auto)`
   并展示摘要卡。软线阈值默认 `llm.yaml` 的 `auto_compact_tokens`（≈ 上下文窗口 × 0.90）。
   **只有真正超阈值才触发**，不会每轮重复；手动 `/compact` 之后也不会再重复触发。
3. **硬线兜底**：每轮发消息前若 token 已超「硬线阈值」（≈ 窗口 × 0.95），直接丢弃最旧消息到安全水位
   （不调用 LLM），保证请求绝不超窗；前端收到 `compaction(trigger=hard_trim)`。

阈值可在「设置 → 我的 APIKey」的模型配置里按 `auto_compact_tokens` / `hard_limit_tokens` 单独覆盖；
留空则按窗口比例（0.90 / 0.95）自动派生。

**快速演示自动压缩（低阈值启动）**：

```bash
cd backend
AGENT_SOFT_LIMIT=1200 AGENT_HARD_LIMIT=1600 AGENT_KEEP_MESSAGES=4 python run.py
```

- 触发后：仅在 token 真正超过软线阈值的轮次出现一张自动摘要卡；`compaction` 字段更新为已压缩。
  阈值设得过小时（单轮回复就超阈值）会每轮触发属正常；日常用默认阈值不会。

### 4.2 已知边界（MVP 范围）

- 认证为邮箱+密码（bcrypt），access token 为 JWT，refresh 走 HttpOnly cookie；未做邮箱验证/找回密码/OAuth。
- 单副本运行；停止生成为进程内取消（未做跨实例协调）。
- 多 MCP 服务器：**已支持聚合**（逐个连接，成功者工具合并；个别连接失败降级跳过，不影响其它）。
- 若全部服务器都连不上，退回内置 demo 工具集，保证 Agent 仍可用。
- `llm.yaml` 只读（含真实 key，已在 `.gitignore` 忽略）；用户级 key 存于 SQLite（明文列，仅本机 MVP）。
- **自动压缩已知遗留**：若单个模型的单次回复本身极大（远超软线阈值的一部分），自动压缩后仍需保留
  「最近 2 条」，会包含这条超大回复，导致下一轮 `after_tokens` 仍超阈值而**连续二次触发压缩**。
  这不是误报（确实超阈值），硬线兜底仍保证不超窗，但摘要次数偏多、近期细节可能被摘要掉。
  处理方案见 `docs/20261104-上下文压缩方案与进度.md` §7.1（尚未实施）。

### 4.5 消息块顺序（2026-11-04 修复）

问题现象：图明明是本轮最后产物，页面上却显示在最前面。

根因（两处都写死了顺序）：

1. 后端 `_persist` 按「text → chart → tool」分组落库，丢掉事件真实顺序；
2. 前端 `MessageList` 固定按「summary → chart → tool → 文本」渲染，且流式期间用
   `rebuildBlocks(content, tools, charts)` 每次重建，同样按类型分组。

修复：

- 后端改为**按事件顺序累积** `blocks`：文本增量并入末尾文本块，`tool`/`chart` 插入当前位置。
- 前端流式期间同样按事件顺序 `appendTextBlock` / `appendBlock`，不再按类型重建。
- `MessageList` 改为直接遍历 `msg.blocks` 渲染，顺序即数据顺序。
- 兼容旧数据：`db._row_to_message` 用 `_normalize_legacy_blocks` 识别旧格式
  （唯一 text 块在最前、其余为 tool/chart），把 text 移到末尾。新格式不受影响。

验证（真实请求）：

```text
NEW ORDER:    text(14) → tool:metric_search → tool:time_options → tool:metric_series
              → tool:chart_spec → chart:line → text(284)
LEGACY ORDER: chart:line → tool:* → text(173)   # 旧会话经 API 读取后已归一化
```

### 4.6 “看起来不是流式”根因（2026-11-04 修复，重要）

现象：思考、工具卡片、工具结果、图表、文本**几乎同时出现**，像一次性渲染。

排查证据（三层测量）：

| 层 | 观测 | 结论 |
|---|---|---|
| 后端 SSE（Python urllib 直读） | `message_start` 0.04s，`tool_start` 5.4s，`chart` 12.7s，`done` 17.4s；`text_delta` 296 个、跨度 13s | 后端**确实在流式**，不是缓冲 |
| 浏览器 fetch 拦截（记录每个 frame 到达时刻） | 5.48s 收到首个 `text_delta`，一直持续到 19s | 网络层**确实在流式** |
| DOM 轮询（每 80–200ms） | 0–17s DOM **完全不变**，最后一次性出现 4 个工具卡 + 图表 + 全文 | **前端渲染**才是问题 |
| CDP Profiler | 主线程 idle 18.8s（无长任务） | 不是主线程阻塞 |

**根因**：`frontend/src/api.ts` 的 `parseFrame` 只把 `data:` 行 JSON 传给 `onEvent`，
丢掉了 SSE 的 `event:` 行；而后端 `sse_frame` 把事件类型只写在 `event:` 行，`data` 里没有 `type` 字段。
于是 `onEvent` 收到的对象 `ev.type === undefined`，`App.tsx` 里所有 `if/else` 分支全部不匹配，
**一次 `patch()` 都不会执行**；只有流结束后的 `loadMessages()` 全量刷新才把内容显示出来——所以像“一次性渲染”。

**修复**：`parseFrame` 在解析后，若 `data.type` 缺失则用 SSE 事件名补齐：

```ts
if (event && event !== 'message' && typeof data.type !== 'string') data.type = event
```

**修复后实测**（同一问题）：

```text
t=  6.8s  首段文本出现（typing 消失）
t= 10.0s  工具卡 1–2 出现（含参数）
t= 14.1s  工具卡 3 出现
t= 19.4s  图表卡片出现
t= 21.7s+ 文本持续增长（22 → 37 → 50 → 88 → 91 字）
```

**教训**：SSE 的事件类型有两条通道（`event:` 行 / `data.type` 字段），
前端解析必须二选一**归一化**，不能只认其中一条。新增事件类型时也要同步检查这里。

**附**：当前默认模型端点（`deepseek-v4.1-flash`，openai_responses 线）实测**不返回 reasoning 内容**
（chunk 的 `content` 是纯字符串，无 reasoning 块），因此页面不显示思考内容属模型侧行为；
代码里 `extract_reasoning` 已兼容 reasoning 块形态，换到会返回思考的端点即可显示。

### 4.7 “旁白气泡一直挂着 / 与最终答案开头重复”根因（2026-11-04 修复）

现象：工具调用前的一句旁白（如「我先看一下数据结构，然后再取数。」）始终挂在 UI 上，
并且最终答案气泡的开头又出现同一句话。

排查（直接读库）：

```text
blocks = [ text(16) "我先看一下数据结构…" , tool x6 , chart:line , text(192) "图已经…" ]
content = "我先看一下数据结构…图已经…"        # 全部 text_delta 的拼接
```

- **数据是对的**：`blocks` 已按事件顺序保存，旁白与最终答案是两个独立 `text` 块。
- **前端渲染错了**：`renderBlock()` 对 `type === 'text'` 直接 `return null`，
  文本只由 `msg.content`（所有 delta 拼接）渲染一次 → 旁白被并进最终气泡开头，
  而工具卡片渲染在它下面，看起来像“旁白气泡一直挂着”。

修复：

- `renderBlock()` 支持 `text` 块，按它在 `blocks` 中的位置渲染成独立气泡。
- 新增 `hasTextBlocks`：`blocks` 里已有 text 块时不再渲染 `msg.content`（只作为旧数据兜底）。

修复后实测（同一问题）：

```text
5.3s   bubbles=["我会先找到…指标 ID，并查询最近半年全国的数据。"]   tools=0
5.5s   bubbles=[同上]                                            tools=2
10.8s  bubbles=[同上]                                            tools=4 charts=1
12.4s  bubbles=[同上, "全国家庭宽带用户数已在图中展示"]           tools=4 charts=1
```

即：旁白独立成气泡且停在工具之前，最终答案不再重复旁白。

**教训**：`blocks` 是顺序真相，`content` 只是纯文本聚合；两者不能同时渲染，
否则文本会重复且顺序错位。新增块类型时也要同步检查 `renderBlock`。
