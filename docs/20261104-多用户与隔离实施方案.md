# 多用户 + 会话隔离 + 用户级 APIKey / MCP 配置 —— 实施方案与进度

> 本文件是该阶段的方案与台账。基线：项目已有单用户 MVP（见 `docs/20261104-实施方案与进度.md`）。
> 参考：Aivory 的 `后端-01-API路由与认证授权.md`、`多用户写删除操作隔离分析.md` 及其 auth 源码。

---

## 1. 目标

1. **多用户区分登录**：注册 / 登录 / 登出 / 当前用户，JWT access+refresh（对齐 Aivory 形态）。
2. **会话隔离**：每个用户只能看到/操作自己的会话与消息；越权即 404（对齐 Aivory 所有权层）。
3. **每个用户可配置自己的 LLM APIKey**：user 级 LLM 配置（wire_api/base_url/api_key/model/上下文/参数），未配置则回退默认 `llm.yaml`。
4. **每个用户可配置自己的 MCP**：user 级 MCP 服务器（内置 demo 开关 / http / sse / stdio），运行时按用户装配工具。

## 2. Aivory 关键结论（我们照搬的几条铁律）

- 用户表：`users(id,email,password_hash,name,role,status,token_ver,...)`；会话表：`refresh_tokens(jti,user_id,expires_at,revoked,...)`。
- 身份：短时效 access JWT（`Authorization: Bearer` 或 cookie）+ 长时效 refresh JWT（HttpOnly cookie）。
- **所有权层（最关键）**：store 层所有读写/删除函数**强制带 `user_id` 过滤**，`rowcount==0` 即 404；「拿到别人 id 也无法操作」。
- 授权输入（role/status/token_ver）以 DB 为准，不信 JWT 自身。

## 3. 数据模型（SQLite，新增表）

```sql
users(id TEXT PK, email TEXT UNIQUE, password_hash TEXT, name TEXT,
      role TEXT DEFAULT 'user', status TEXT DEFAULT 'active',
      token_ver INTEGER DEFAULT 0, created_at INTEGER)
refresh_tokens(jti TEXT PK, user_id TEXT, expires_at INTEGER,
      revoked INTEGER DEFAULT 0, created_at INTEGER)

-- 用户级 LLM 配置（每行=一条可用模型端点；is_default 选定默认）
user_llm_configs(id TEXT PK, user_id TEXT, label TEXT,
      wire_api TEXT, base_url TEXT, api_key TEXT, model TEXT,
      context_window INTEGER, max_tokens INTEGER, reasoning_effort TEXT,
      is_default INTEGER DEFAULT 0, created_at INTEGER, updated_at INTEGER)

-- 用户级 MCP 服务器（transport: builtin_demo | http | sse | stdio）
user_mcp_servers(id TEXT PK, user_id TEXT, name TEXT, transport TEXT,
      command TEXT DEFAULT '', url TEXT DEFAULT '', headers TEXT DEFAULT '{}',
      enabled INTEGER DEFAULT 1, created_at INTEGER, updated_at INTEGER)
```

现有 `sessions`/`messages` 增加 `user_id`（sessions 已有 `user_id` 默认 'local'，改造为真实用户）。

## 4. API 契约（新增/改造）

### 4.1 认证
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/register` | `{email,password,name?}` → 建用户并直接登录 |
| POST | `/api/auth/login` | `{email,password}` → `{user, access_token, expires_at}` + set cookies |
| POST | `/api/auth/logout` | 清 cookie、撤销 refresh |
| GET | `/api/auth/me` | 当前用户（401 若未登录） |
| POST | `/api/auth/refresh` | 用 refresh cookie 换新 access |

### 4.2 用户设置（需登录）
| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | `/api/me/llm-configs` | 列出/新增用户 LLM 配置（api_key 打码返回） |
| PATCH/DELETE | `/api/me/llm-configs/{id}` | 改/删（仅本人） |
| GET/POST | `/api/me/mcp-servers` | 列出/新增用户 MCP |
| PATCH/DELETE | `/api/me/mcp-servers/{id}` | 改/删（仅本人） |
| GET | `/api/me/mcp-effective` | 当前生效的工具名列表（调试） |

### 4.3 会话（全部需登录 + 按 user_id 过滤）
保持 `/api/sessions*` 不变，但每个 handler 依赖 `current_user`，DAO 全部带 `user_id`；越权访问返回 404。

## 5. 运行时改造

- 一个全局 `AsyncSqliteSaver`（checkpoint 共享，thread_id=session_id 全局唯一）。
- **按用户懒构建 runtime**：`RuntimeHub.get(user_id)` → `{model, toolset, agent}`；用户 LLM/MCP 配置变更时 `invalidate(user_id)` 重建。
- 模型解析：用户默认 `user_llm_configs`（且有 api_key）→ 否则回退 `llm.yaml` default。
- 工具装配：用户 MCP 配置（builtin_demo 用内置 5 工具 / http/sse/stdio 用 fastmcp.Client 连接）→ LangChain 工具；连接失败降级为空并记录。

## 6. 前端改造

- 登录/注册页；未登录跳转。
- `api.ts` 注入 `Authorization: Bearer`，401 回登录。
- 设置面板：管理「我的 APIKey」与「我的 MCP」。
- 侧栏显示当前用户 + 登出；会话列表本身就是该用户的（后端隔离）。
