## 1. 三条硬规则

### 规则 1：推翻旧结论时，必须找一条「不依赖我的推理」的旁证

**反面案例（本次真实事故）**

我判定「`Aue()` 是记忆工具模式开关」，并据此在文档里更正了旧版。
推理链是：`Aue()` = `QLt() && (qyt() || ttn())` → `QLt()` 读 `Vmt()`
→ `Vmt()` 读 `blockReadsOutsideWorkingDirectories` → 所以它是权限守卫。

这条推理**碰巧是对的**，但在返工前我没有旁证。真正让我确认的是
`m0293_0x1177df9f.js:4801` 的一行遥测：

```js
l("tengu_memdir_disabled", {
  disabled_by_env_var: ke,
  disabled_by_setting: !ke && yt().autoMemoryEnabled === !1,
  read_block_fenced: Aue()          // ← 字段名字面意思：读取被「围栏」挡住
})
```

**字段名 `read_block_fenced` 是 Anthropic 自己写的，它替我证明了语义。**

可用的旁证类型，按可靠性排序：

| 类型 | 例子 | 可靠性 |
|---|---|---|
| **遥测事件名 / 字段名** | `tengu_attachment_compute_duration`、`read_block_fenced` | 最高——作者为了让数据可读才这么起名 |
| **面向用户的提示词原文** | `"lines after 200 will be truncated, so keep the index concise"` | 极高——直接说明行为契约 |
| **常量名 / 错误码** | `MAX_SESSION_BYTES`、`platform` 类错误字符串 | 高 |
| **schema 的 `.describe()`** | `"Scope for auto-loading agent memory files"` | 高——但可能是过时注释，需交叉验证 |
| **函数名（压缩后可能丢失）** | `function zTe` / `function Aue` | 低——minify 后名字无意义 |

**操作要求**：任何「旧文档错了」的判断，落笔前必须能指出至少一条上表前四类的旁证。
找不到就写「疑似」，不要写「更正」。

### 规则 2：import 图不是证据——先查这个 chunk 被多少模块共用

**反面案例（本次真实弯路）**

我想确认 `m0591` 里的 `lSe` 来自 `m0191`，做法是看 import：

```js
// m0591:825
lSe,
...
} from "B:/~BUN/root/chunk-1ks9vs37.js";   // ← 想据此说「来自 m0191」
```

然后发现 `chunk-1ks9vs37.js` 被 **1263 个模块**引用。这是个公共 chunk，
import 图在这个粒度上**完全不构成归属证据**。

**正确的判据**：看这批符号是否**成组**由同一个模块导出。

```js
// m0591 的同一个 import 块里
fh, lSe, K$t, EU, Dz, vl, uJ, R4, bie, mC, ...
```

这 8 个符号 + `EU/vl/uJ`（记忆根解析）在语义上是一组，且逐个查 m0191 的
export 清单全部命中 → 归属成立。**成组 + 语义自洽，才够。**

**操作要求**：

1. 看到 `chunk-xxx.js` 导入，先数它被多少文件引用；
2. 引用数 > 50（公共 chunk），**不要**用 import 图定归属；
3. 改用「同 import 块的符号是否成组导出」「是否与已知语义聚在一起」判断；
4. 最终结论里如果要写「X 定义在模块 M」，必须能给出符号级别的判据。

**这个 repo 的分割口径**（见 `claudecode319/MANIFEST.md`）是按
`// @bun @bytecode` marker 切的 span，**不是原始模块边界**。共享 chunk 大量存在，
所以同号模块在不同版本间也不可平移（MANIFEST 已明确警告「禁止用模块号直接套用」）。

### 规则 3：断言「X 进了上下文」必须走到最终拼装点

**反面案例（本次真实事故）**

首版写「`MEMORY.md` 每次会话都进上下文」，证据只给到 `m0591:70580`：

```js
if (ar) {
  let Tr = Cp(ar.path);
  if (!Y.has(Tr)) Y.add(Tr), G.push(ar)      // ← 只加到数组 G
}
```

**加到数组 ≠ 进上下文。** 数组后面还要过滤、拼装、再塞进 blocks。返工后补到：

```js
// m0591:71183
let Xe = Ye === void 0 ? void 0 : xe ? ve.claudeMd : WQe(Ye),   // ← 拼成文本
    pt = Object.fromEntries(Re.blocks.map(({name: ot, text: Ze}) =>
      [ot, ot === "claudeMd" && Xe !== void 0 ? Xe : Ze]));      // ← 进 blocks.claudeMd
```

证据链**四段**：加载（`:70580`）→ 数组（`G.push`）→ 拼装（`WQe`）→ `blocks.claudeMd`（`:71183`）。
少任何一段，结论都可能是错的（过滤条件、`xe` 分支、`Ye === undefined` 都能让它落空）。

**操作要求**：这类断言至少给出四段，缺一段就降级措辞为「疑似会注入」。

## 2. 措辞纪律

本次返工修正的第三类问题不是事实错，是**话说大了**：

| 写成了 | 实际是 | 正确措辞 |
|---|---|---|
| 「CC 无独立 delete 工具」 | 客户端已知名单 `Nji` 只有三个，但工具闸白名单 `z$t` 里有 `memory_delete` | 「对外契约只声明三件套；不否定服务端存在 delete」 |
| 「只有 Edit/Write 触发」 | 还有 Read 类 `readProbe` 路径、两处写文件实现 | 「Edit/Write 是主路径；另有探测期路径」 |
| 「注册成 `post_turn_memory` 任务」 | 只在 `config.declareTask` 为真时注册 | 「可注册为；默认取决于配置」 |

**判定方法**：写完一句结论，问「有没有一个配置项 / 一个分支能让它不成立？」
有 → 必须写进结论或降级为「默认情况」。

## 3. 返工时的检查清单

怀疑自己的文档时，按这个顺序查（本次实测有效）：

1. **专攻「我推翻了旧文档」的那些条目** —— 错误集中在这里。
   推翻别人的成本低、心理阻力小，最容易草率。
2. **专攻「证据只有一行」的条目** —— 通常没走到终态。
3. **专攻措辞里的绝对词** —— 「只有」「全部」「无」「一定」「每次」。
   逐个去找反例分支。
4. **重跑行号校验** —— 但注意：全过只说明引号没写错，不代表结论对（见 §0）。
5. **抽查 3 个「我最有把握」的结论** —— 返工的价值往往在这里最高，
   因为最有把握的如果错了，说明判据本身有问题。

## 4. 与 §2.4 判据分级的关系

`AGENTS.md` §2.4 说得很清楚（L1 机制已实现 / L2 机制已触发 / L3 用户看到了）。
本次调研**全部属于 L1**：静态阅读源码，没有任何运行时证据。

所以文档里不能说「CC 运行时确实这样」。要升到 L2/L3 需要：

- 带 `CLAUDE_MEMORY_STORES` 跑一次会话，抓 `tengu_memdir_prefetch_collected` 遥测，
  验证 `consumed_on_iteration` 的实际取值；
- 或 `CLAUDE_CODE_POST_TURN_MEMORY=1` 抓 `[extractMemories]` 的 tlog。

**结论只到 L1 就必须在文档里写明只到 L1。** 本次已写在 v2 文档 §15 之后的局限说明里。
