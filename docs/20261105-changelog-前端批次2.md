# 前端批次 2：消息流去气泡 —— 完成记录

## 一、目标

把消息流从「全气泡」改为三层信息模型：文本内容零容器，过程层（思考/工具/摘要）轻量化，
容器只留给「用户输入」这一种语义。同时修掉 AI 回复气泡过窄、正文被框限制的问题。

**关键约束（用户明确要求）**：不是「所有东西都去气泡」——只去**文本内容**的气泡，其他保留容器语义。

## 二、实际改动

### 2.1 `frontend/src/components/MessageList.tsx`（188 → 约 250 行）

1. **删除消息流头像**：移除 `.msg` 内的 `avatar` 节点；仅保留侧栏用户小头像（`Sidebar.tsx` 的 `.avatar` 未动）。
2. **文本按 role 分流渲染**：
   - user → `<div className="bubble">`（保留输入容器）
   - assistant → `<div className="answer"><Markdown/></div>`（零容器）
   - 旧的 `msg.content` 兜底路径同样分流，不再统一套 `.bubble`。
3. **`ToolCard` → `StepRow` + `StepGroup`**：
   - 单行：状态点 + 工具名 + 参数摘要（path/command/query 等关键字段优先，截断 90 字）。
   - 完成态只显示绿点（不重复写「完成」，降噪）；运行中/失败才显示状态文字。
   - 点击展开 `参数 / 结果`，用 `--surface` 浅底块。
   - 连续 tool block 合并成组，组头显示「N 个步骤 · 全部完成 / 有失败 / 运行中」。
4. **`ReasoningSection` 改默认折叠单行**：`思考 · 572 字`，展开才渲染正文；live 时自动展开并带光标。
5. **`SummaryCard` 降为细胶囊**：`--surface-2` 底、12px，点击展开摘要正文。
6. **顺序不变**：仍按 `blocks` 数组真实事件顺序渲染；连续 tool 合并只在「相邻且都是 tool」时发生，
   绝不跨 text / reasoning 重排。`chat.py` 的 reasoning 顺序逻辑未改动。

## 六、批次 2 缺陷修复（2026-11-05 追加）

### 6.1 现象

流式生成期间，**同一轮里较早的思考块**也带橘色光标（像是还在输出），并且底部还会额外出现一个
「正在思考」指示器，与 live 思考块状态重复。

### 6.2 根因

`renderBlocks(blocks, isUser, live)` 把 `live`（= 整条消息是否 streaming）**原样传给了该消息里的
每一个 reasoning 块**：

```tsx
out.push(<ReasoningSection ... live={live} />)   // 旧：所有理由块共用同一个 live
```

只要消息还在流式，历史上已结束的思考块就被判为 live，于是全部展开、全部带光标。

### 6.3 修复

1. 只有 **blocks 中最后一个块**且消息仍在 streaming 时才算 live：
   ```tsx
   const liveIdx = streaming ? blocks.length - 1 : -1
   ...
   <ReasoningSection ... live={i === liveIdx} />
   ```
   最后一块是 tool / text 时，则没有任何思考块是 live —— 符合“思考 -> 工具 -> 文本”的实际时序。
2. 「正在思考」占位指示器增加 `!hasReasoningBlocks` 条件，已有 live 思考块时不再重复显示。

### 6.4 验证

用 Playwright 拦截 `/api/sessions/co_fake_live` 注入一条 `status=streaming`、含两个 reasoning 块
（中间夹一个 tool）的 assistant 消息：

| 位置 | 标题 | live | 状态点 | 展开 | 光标 |
|---|---|---|---|---|---|
| 第 1 个思考块 | 思考 | false | `done`（绿） | 折叠 | 无 |
| 第 2 个思考块（末尾） | 思考中 | true | `running`（橙，呼吸） | 展开 | `▊` |

- 1440 / 390 两档结果一致；`.typing` 节点数 = 0（重复指示器已消除）；控制台 0 error。
- 真实历史会话回归：`E2E-sqlbot`（1 块）、`你介绍一下姆巴佩`（5 块）——全部 `live=false`、
  `caret=none`，即**已完成的思考块不会再出现橘色光标**。
- 后端 `pytest -q` → **25 passed**。
