## 1. 启用 A2A（后端）

A2A 默认关闭；不设置 `INNER_A2A_ENABLED=true` 时，AgentCard、JSON-RPC、token API 都返回 404。

```powershell
cd D:\git_codes\inner_chatgpt\backend
$env:INNER_A2A_ENABLED="true"
$env:INNER_A2A_PUBLIC_BASE_URL="http://127.0.0.1:8000"   # 生产改成 https://你的域名
$env:INNER_A2A_SYNC_TIMEOUT_S="60"
python run.py
```

生产环境注意：

- 必须 HTTPS；
- `INNER_A2A_PUBLIC_BASE_URL` 必须是外部客户端实际能访问的地址（反代后的公网/内网地址），否则 AgentCard 里的 `url` 会写成内部地址；
- 不建议把 A2A 端点直接暴露到公网而不加 WAF/限流。

## 2. 在页面上创建 token

1. 登录 Hlaudz；
2. 打开「我的设置 → A2A 接入」；
3. 页面会显示当前用户的：
   - A2A Endpoint
   - AgentCard URL
   - tenant
4. 填 token 名称和有效期，点「创建 A2A Token」；
5. **明文 token 只显示这一次**，复制后保存到安全的密码管理器/环境变量；
6. 不再需要时，在同一页面点「撤销」。

## 5. 发消息

### 5.1 同步发送（推荐先这样验证）

```powershell
$env:A2A_TOKEN = "hlz_a2a_你的token"

a2a send `
  -a $CARD `
  --tenant $AGENT_ID `
  --auth "Bearer $env:A2A_TOKEN" `
  --timeout 120s `
  -o json `
  "只回复：A2A ACCEPT OK"
```

实际返回（本次验收）：

```json
{
  "task": {
    "id": "task_cce6a632443639c3",
    "contextId": "co_963b1c612f8a",
    "status": {"state": "TASK_STATE_COMPLETED", "timestamp": "2026-11-09T16:47:13.084Z"},
    "artifacts": [
      {"artifactId": "answer", "name": "answer", "parts": [{"text": "A2A ACCEPT OK"}]}
    ]
  }
}
```

- `task.id` 是 A2A 任务 id，后续 `GetTask` / `CancelTask` 都用它；
- `task.contextId` 是 Hlaudz 的会话 id，后续多轮对话把它传回去；
- 最终答复在 `artifacts[].parts[].text`；
- 如果任务超过 `--timeout`，客户端会报超时；长任务用下面的异步方式。

### 5.2 异步发送 + 轮询

```powershell
a2a send -a $CARD --tenant $AGENT_ID --auth "Bearer $env:A2A_TOKEN" `
  --async -o json "写一篇约1500字的文章，主题是异构智能体互操作"

a2a task get -a $CARD --tenant $AGENT_ID --auth "Bearer $env:A2A_TOKEN" `
  <task-id> --wait --timeout 180s
```

本次验收的异步任务：

```text
task_a090a9c9a02bc9e7   -> 已取消 TASK_STATE_CANCELED
```

### 5.3 取消

```powershell
a2a task cancel -a $CARD --tenant $AGENT_ID --auth "Bearer $env:A2A_TOKEN" <task-id>
```

返回任务状态 `TASK_STATE_CANCELED`。实际取消会复用 Hlaudz 现有停止路径，级联清理 ACP/子 agent/code_run。

### 5.4 同一 context 继续对话

```powershell
a2a send -a $CARD --tenant $AGENT_ID --auth "Bearer $env:A2A_TOKEN" `
  --context-id co_963b1c612f8a `
  --timeout 120s -o json "只回复：CONTEXT OK"
```

本次验收：

```text
task_371fd08e4ed003d8
contextId = co_963b1c612f8a
artifact  = CONTEXT OK
```

### 5.5 幂等（重试安全）

同一个 `messageId` 重复发送，Hlaudz 返回第一次的 task，不会重复执行：

```powershell
$payload = '{"message":{"messageId":"accept-idem-20261110","role":"ROLE_USER","parts":[{"text":"只回复：IDEM ACCEPT OK"}]}}'

a2a send -a $CARD --tenant $AGENT_ID --auth "Bearer $env:A2A_TOKEN" --request-payload $payload --timeout 120s -o json
a2a send -a $CARD --tenant $AGENT_ID --auth "Bearer $env:A2A_TOKEN" --request-payload $payload --timeout 120s -o json
```

本次两次都返回：

```text
task_b236f0c5e3d53911
artifact = IDEM ACCEPT OK
```

### 5.6 真正的流式（SSE）

AgentCard 当前是 `"streaming": true`。A2A CLI 用 `--stream` 会走
`SendStreamingMessage`，服务端逐条返回 SSE：

```powershell
a2a send -a $CARD --tenant $AGENT_ID --auth "Bearer $env:A2A_TOKEN" `
  --stream --timeout 120s -o jsonl "只回复：STREAM REAL OK"
```

本次真实验收输出（节选）：

```text
{"task":{"id":"task_c752ed240073ea46","contextId":"co_ec625ef10a8f","status":{"state":"TASK_STATE_SUBMITTED",...}}}
{"statusUpdate":{"taskId":"task_c752ed240073ea46","status":{"state":"TASK_STATE_WORKING",...}}}
{"artifactUpdate":{"append":true,"artifact":{"artifactId":"answer","parts":[{"text":"F"}]},...}}
{"artifactUpdate":{"append":true,"artifact":{"artifactId":"answer","parts":[{"text":"INAL STREAM OK"}]},...}}
{"statusUpdate":{"taskId":"task_c752ed240073ea46","status":{"state":"TASK_STATE_COMPLETED",...}}}
```

拼接 `artifactUpdate` 的 `parts[].text` 得到 `FINAL STREAM OK`。

`SubscribeToTask` 用于任务已经启动后重新订阅；本次验收：

```powershell
a2a task subscribe -a $CARD --tenant $AGENT_ID --auth "Bearer $env:A2A_TOKEN" `
  --timeout 120s -o jsonl task_da1ee80752313fdd
```

它会先回放进程内事件日志，再继续接收后续事件；服务重启后旧任务没有日志可回放，
`GetTask` 仍可查最终状态。

## 6. 查询与错误

### 6.1 GetTask

```powershell
a2a task get -a $CARD --tenant $AGENT_ID --auth "Bearer $env:A2A_TOKEN" `
  task_cce6a632443639c3 -o json
```

### 6.2 ListTasks

```powershell
a2a task list -a $CARD --tenant $AGENT_ID --auth "Bearer $env:A2A_TOKEN" --limit 5 -o json
```

### 6.3 常见错误

| 返回 | 含义 | 处理 |
| --- | --- | --- |
| HTTP 401 `a2a_auth_required` | 没带 Bearer | 加 `--auth "Bearer ..."` |
| HTTP 401 `a2a_invalid_token` | token 不存在/拼错 | 重新从设置页复制 |
| HTTP 401 `a2a_token_revoked` | token 已撤销 | 重新创建 token |
| HTTP 401 `a2a_token_expired` | token 过期 | 重新创建 token |
| HTTP 403 `a2a_agent_mismatch` | token 不属于这个 agent_id | 用 token 对应的用户 URL |
| HTTP 403 `a2a_tenant_mismatch` | `--tenant` 与 agent_id 不一致 | 用卡片里的 tenant |
| HTTP 404 `agent_not_found` | agent_id 不存在 | 检查卡片 URL |
| JSON-RPC `-32601` | 方法未实现/拼错 | 当前支持 `SendMessage` / `SendStreamingMessage` / `GetTask` / `ListTasks` / `CancelTask` / `SubscribeToTask` |
| JSON-RPC `-32001` | 任务/context 不存在，或任务已终态不可取消 | 用 `GetTask` 确认状态 |

### 6.4 超时/长任务

- `a2a send` 默认超时 30s；Hlaudz 侧默认最多等待 60s；
- 长任务用 `--timeout 120s`，或 `--async` 后 `task get --wait`；
- 不要用很短的 `--timeout` 去调用会跑工具的复杂任务。

## 7. 不用 CLI 时：直接 HTTP JSON-RPC

A2A 是标准 JSON-RPC，任何 HTTP 客户端都能调：

```powershell
curl -X POST "$BASE/a2a/$AGENT_ID" `
  -H "Authorization: Bearer $env:A2A_TOKEN" `
  -H "Content-Type: application/json" `
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "SendMessage",
    "params": {
      "tenant": "ha_2947592215cfb5f6",
      "message": {
        "messageId": "curl-001",
        "role": "ROLE_USER",
        "parts": [{"text": "只回复：CURL OK"}]
      }
    }
  }'
```

成功时 `result` 是 `{"task": {...}}`；`GetTask`/`CancelTask` 的 `result` 直接是 Task 对象（不是包一层 `task`）。

## 8. 权限与安全模型

- **每个用户一个 agent_id + 一套 token**；没有全局可调用的总入口。
- 每次请求做三方绑定：
  1. `Authorization: Bearer` 的 token；
  2. URL 里的 `agent_id`；
  3. 请求体里的 `tenant`。
  任何一项不匹配 → 401/403。
- token 只存 SHA-256，不存明文；支持撤销、过期、最近使用时间。
- 当前 MVP 只允许 `chat` scope；`files:read` / `files:write` / `tools:run` / `agent:spawn` 还没有开放到工具策略层。
- 外部调用消耗的是**该用户自己的模型配置和额度**。
- 不要把 token 写进 prompt、URL query、日志或 Git；用环境变量/密码管理器。
- 生产环境必须 HTTPS，并建议加反向代理限流和审计。

## 9. 当前限制（务必知道）

1. push notifications 未实现；`SendStreamingMessage` / `SubscribeToTask` 已支持进程内流式。
2. scope 只接受 `chat`，且工具层尚未按 scope 做硬门禁；不要把端点暴露给不可信调用方。
3. 并发配额配置项已定义，MVP 还未强制。
4. 单实例 SQLite + 进程内任务；服务重启会把 `SUBMITTED/WORKING` 任务标记为 `FAILED`。
5. 只支持 A2A v1.0 的 PascalCase 方法，不做 v0.3 小写别名。
6. AgentCard 是通用卡片，不含用户隐私/模型配置。
7. 没有审计表和速率限制。
