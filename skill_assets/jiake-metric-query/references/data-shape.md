# 数据形态快照

> 来源：`sqlbot_mcp` 演示数据集 `data/sqlbot.db`（SQLite，随仓库分发）。
> 采集方式：直连数据库统计 + MCP 工具返回值交叉验证。
> 这些数字是**某一时点的快照**，上线环境若换库会不同；每次查询仍应以
> `time_options()` / `table_schema()` 的实时返回为准。

## 1. 三张表

| 表 | 行数 | 实际列 | 说明 |
|---|---|---|---|
| `ads_jk_business_metric_dictionary` | 635 | `id`, `metric_name_cn` | 指标字典。**注意：实际只有 2 列** |
| `ads_jk_business_metric_values` | 746,760 | `data_time`, `zone_id`, `dictionary_id`, `time_granularity`, `metric_value` | 指标值 |
| `d_zone_info` | 49 | `zone_id`, `zone_name`, `parent_id`, `zone_level` | 区域字典 |

> ⚠️ 逻辑 schema（`dimensions` / `table_schema` 返回的注释版）里，
> 指标字典列有 `module_name` / `metric_name_en` / `unit` / `is_delete`，
> 但**实际演示库里这些列不存在**。写 SQL 时只能用 `id` 与 `metric_name_cn`。
> `metric_list` / `metric_search` 的 `module_name` / `unit` 字段恒为 `null` 就是这个原因。

## 2. 时间

| 项 | 值 |
|---|---|
| 最早数据 | `2024-08-01` |
| 最新数据 | `2026-07-01` |
| 总行数 | 746,760 |
| **有数据的粒度** | **只有 `time_granularity = 2`（月）** |
| `gran=1`（天）行数 | 0 |
| `gran=3`（季度）行数 | 0 |

- 月粒度 `data_time` 固定为每月 1 日（`2026-07-01` 代表 2026 年 7 月）。
- 区间长度 24 个月（2024-08 ~ 2026-07）。
- 635 个指标**每个都有数据**（`count(distinct dictionary_id) = 635`），
  单指标单区域有 1176 行（= 49 区域 × 24 月）。
